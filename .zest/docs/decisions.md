# 设计决策

## D-027：项目文档统一在 .zest/docs/ 维护

日期：2026-10-17。状态：产品所有者确认，本轮实现基础能力。

共享 API、业务规则、架构及设计决策属于团队项目知识，保存在 `.zest/docs/` 并随 Git 版本共享。
目录中的文字文件可被读取、检索、调查，也可被明确指定为开发修改目标。
其他 `.zest/` 资源默认留在本地；可移植部分不携带绝对路径、用户的本地项目身份或执行许可。
新克隆工作区创建自己的登记身份和数据库，读取相同提交中的项目文档。

`.zest/.gitignore` 为可共享的布局配置，只放行 docs 目录中允许的文档类型。
根忽略规则排除整个 `.zest/` 时，显式文档初始化仅追加父目录的放行规则，保留原内容。
现有自定义 `.zest/.gitignore` 不自动覆盖；缺少工作区身份的任意非空本地状态仍不接管。

## D-028：迁入是保留来源的本地改动

日期：2026-10-17。状态：实现。

显式初始化从选定的已提交 Git 版本读取根文档及 `doc/`、`docs/` 下的允许文本，
复制到 `.zest/docs/imported/`，以 `imports.json` 保存原路径、commit、blob 与内容哈希。
原文保留；未提交内容不冒充版本化来源。迁入资料标为待核实，不自动转为人工确认知识。

已有共享文档不被覆盖。原来源或目标内容发生冲突时返回冲突，交由后续明确的文档维护处理。
重复调用不重写未变化文档，不修改 Git 暂存区、HEAD 或原工作流批准记录。
首次生成的是资料导航，不生成无依据的需求、API 或架构结论。

## D-029：读取项目文档不扩大修改权限

日期：2026-10-17。状态：实现。

共享文档作为对应 Git 版本的来源接入问答、词法索引、项目调查及开发建议。
旧位置文档可继续作为迁入来源或历史参考，不由 Zest 修改。
开发建议自动参考文档时，这些来源是只读的；只有明确指定的目标才能成为候选修改。
文档不是执行授权，也不能单独证明代码行为、测试成功或生产部署。

## D-030：连续执行与最终审阅

日期：2026-10-17。状态：产品所有者确认，完整流程待实现。

需求不清时与开发者持续确认；明确后连续执行开发和测试。
完成后先交付可检查的本地改动，不自动提交或推送。
此产品交互将替代把每个内部模块单独展示给使用者的方式；本轮不提前改写历史任务或重放请求。

## D-031：按项目授权自动理解，资料容量由执行器处理

日期：2026-10-23。依据：用户要求借鉴 OpenWiki 并按研究方案继续优化；阶段 A 已实现。

文档调查在项目持续授权内连续进行，范围内检索、分页、补读和上下文分批不再逐项审批。
摸底样本不再限定后续可读来源；固定 commit 与来源记录用于证据一致性，而非限制为少量文件。
内部执行规则和同一模型下的密钥更新不单独使持续授权失效，模型数据去向或访问权限变化仍需核对。
旧任务与旧批准保持原样，结果未知不自动重发；整轮预算和收据继续保留。
实现与验证边界见 [项目范围读取](project-source-access.md)。工程文档 Writer 与页面级增量仍待阶段 B/C。
