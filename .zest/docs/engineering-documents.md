# 工程文档生成与页面恢复

M131 实现 OpenWiki 改造计划的页面写作阶段。新初始化、补全和增量维护可以把调查事实
组织成面向读者的工程文档；六类调查档案继续保存证据和覆盖情况，不再固定决定页面数量。

## 从调查到页面

1. 调查工作流先读取固定 Git 提交并核对事实，推测、失效结论及未通过核对的部分不进入 Writer。
2. `document_plan` 根据全部可用事实规划主题页，说明读者问题、标题、摘要、事实归属和关联页面。
   页面可以按领域、模块协作或业务流程组织；不是把目录树或六个档案栏目直接复制成六页。
3. `document_write` 为每页撰写连贯 Markdown，可使用表格、步骤、代码片段。
   正文块关联一个或多个事实，不要求每句话后面插入原始记录与 UUID。
4. `document_review` 检查全部正文块与资料限制，结合事实和原始证据复核主体、条件和断言，
   同时检查连贯性、重复小节及运行状态表述；哈希一致不代替语义核对。
5. 程序生成元信息、标题、来源清单及导航，逐页保存、核对落盘哈希，再将该页标为完成。

目前 Writer 复用调查阶段已读取、已核对的事实和原文，不单独发起新事实调查。
资料不足时保留限制；参数、命令、架构关系及运行结果不能在写作阶段凭空补全。
M136 已完成一次真实 BlindBox 文档轮次，5 页通过模型复核并保存；这验证了该轮的生成与恢复，
不代替对全文准确性、项目运行或大项目稳定性的独立验收。离线夹具只证明流程行为。

每轮最多规划 6 页，实际数量还受剩余总预算约束：规划一次，每页写作、复核各一次。
六页只是当前试用容量，不是工程文档必须包含的六个类型。每页最多 12 块、18000 字符；
模型响应预算 4096 token，实际输出通常更短。源码原文不截半条以伪装满足容量。
规划或单页所需内容不能放入完整请求时明确保留未完成状态，不声称大项目必然一次完成。

所有新增请求计入原调查的 32 次物理调用、30 分钟预算；不另开写作预算。
实际 SDK 请求仍受 48000 字符上限约束，保存完整请求及响应收据。
已知格式错误沿用有完整收据的有界补试；结果不明的请求不会自动重发。

## 文档、页面记录与知识缺口

生成页位于 `.zest/docs/initialization/<slug>.md`。`index.md` 按实际页面生成入口，
页面包括标题、摘要、观察提交、解释性正文、必要资料限制、继续阅读和末尾来源。
Web 按生成标题显示目录，并渲染标题层级、表格、列表与代码；原生 HTML 作为普通文本处理。

私有页面账本保存于对应认知存储的 `document-pages/<run-id>.json`。
它绑定调查、批准包、事实快照、页面计划、正文、正文事实关联、复核结果和发布哈希。
请求尝试和物理调用数继续保存在 `cognition.sqlite3`，不维护另一套计费计数。

| 页面状态 | 含义 |
| --- | --- |
| pending / writing | 尚未撰写，或准备写作请求 |
| reviewing | 已保存正文，准备复核 |
| ready | 已通过复核，等待写入 |
| completed | 页面已落盘并校验 |
| skipped | 原文有人工修改，保留原文并输出候选 |
| failed | 格式、语义、预算或写盘等步骤未完成，具体错误保留在私有记录 |
| unknown | 请求结果不明，不能自动重发 |

页面状态与知识缺口分别展示。写盘错误、模型调用错误不作为项目知识写进共享文档；
页面完成也不表示项目知识已穷尽。原始调查的缺口、待明确问题和外部资料需求仍保留在项目状态。

## 保留人工修改与恢复

只有文件当前哈希等于已保存的生成版本，或内容与本次产物完全一致时，程序才更新该文件。
发现人工修改时保留原文，在 `initialization/candidates/<run-id>/<slug>.md` 输出候选，
由索引提供阅读入口；候选自身若也被修改，同样不会覆盖。

单页写作或复核失败不覆盖前一版，也不阻止其他页发布。索引标明保留旧版的页面。
新规划失败时保留原有导航，不以空目录替换已有文档。

初始化的“继续未完成页面”沿用 `initialization.recover`；增量文档沿用 `maintenance.resume`。
已完成请求复用账本响应，已完成页面不再调用模型；写盘失败可直接复用已复核正文。
旧任务的已知语义拒绝不自动改写；M136 新文档轮次支持下述有界修订，未知请求仍须先核对原收据。
只读状态接口不启动写作。`initialization.republish` 只用已保存正文/旧档案本地整理，不调用模型。

M135 为增量文档增加明确的新轮次恢复：原调用或时间预算已耗尽、或同一已知响应持续不符合要求时，
`maintenance.resume` 不再无效排队。项目状态给出原因，用户可通过 `maintenance.documents-new-round`
按原任务 ID 和页面账本哈希明确开启新轮次。它新建独立预算和收据，原研究、调用及旧页面账本保持原样；
只允许文档规划、写作和复核，不允许花新预算重新调查。已发布页面保留，剩余页继续。
新轮次的 dossier 引用原核对事实，保留原始来源身份；不复制成新核对结论。
每次模型请求及发布前检查来源快照，来源失效时拒绝继续；存在未知请求也不能借此重发。
具体 Web 操作与预算说明见 [项目更新检查](maintenance.md)。

### M136：新轮次容量、完整证据与有界修订

尚未形成合法页面计划时，新轮次不继承旧轮次失败的 `plan_payload` / `update_payload`，
而按自己的剩余预算计算页面容量；合法计划与完成页仍复用。此前旧轮次剩余预算产生的
`max_pages=1` 被带入新轮次，真实返回的三页计划因此反复遭本地拒绝，现已修复。

新建的仅文档轮次冻结 `evidence_layout=shared_full_proofs_v1`。请求中的同一份完整原文及位置
只出现一次，其余事实通过 proof_id 引用；没有截短原文、合并不同位置或修改事实归属。
旧轮次沿用原请求布局，不能借升级代码改写已保存请求。结构或范围失败展示具体原因。

新布局轮次允许在原 32 次调用/30 分钟预算内，根据已保存复核意见修订正文，并重新独立复核。
请求序号、正文、修订载荷及复核结果全部落账；只有已知失败可进入下一步，未知请求不重放。
冗余段落仅在删除后仍完整覆盖原计划全部事实、且再次通过整页复核时才能省略。
最终修订遗漏事实时，仅结构与其他约束均通过的覆盖缺失可以进入一次定向补充；
不能以只附事实 ID 代替实质说明，也不能通过删掉计划事实来满足覆盖。
原调查自动核对事实与本页可见原文范围在程序生成的说明中区分；涉及该说明的最终复核看到实际说明原文。
发布门槛仍是全部正文块获支持且 `issues=[]`，不将部分通过或旧复核当作最终通过。

原 `index.md` 有人工修改时，保留它，并在 `initialization/candidates/<run-id>/index.md`
生成链接正确的新目录；Web 提供“查看本轮新文档目录”。正文可已完成而维护整体仍因目录冲突为 partial，
此时明确显示“本轮文档已生成，原目录已保留”，不再误导继续生成。
中文标题预览使用增量 UTF-8 解码，避免预览字节边界截断一个汉字后错误退回路径；真实非法编码仍拒绝。

本轮真实记录：BlindBox `8a09d868a75d`，新轮次 `e199509b-b99c-48ef-9895-d1efccfd01d0`，
27/32 次物理调用、5/5 页保存、原调查调用和账本不变。最后一次发送距轮次开始 1786.655 秒，
中间含调试与恢复，不作为速度基准。验收材料位于 `work/m136-validation/`，仍需另做完整项目理解质量评估。

## 兼容与后续

只有新创建且冻结 `document_generation` 契约的项目范围调查执行 Writer。
旧调查继续使用原本的事实列表发布器；失败调查、没有可发布事实的调查也沿用本地整理，
不会因为查看进度或升级代码而自动补发新类型请求。

M131 本身只支持本机按页恢复。后续 M132 已接入 [稳定事实与页面增量维护](incremental-knowledge.md)：
新调查可保留事实身份，按依赖安排局部更新，并保存各页核验/证据检查版本及共享清单。
没有新增契约的旧调查继续使用 M131 的全部页面规划流程。

实现：`zest/document_contracts.py`、`zest/document_pages.py`，由初始化和维护 Worker 调用。
测试：`tests/test_document_pages.py`、模型 Schema/传输契约、初始化/维护回归与前端文档测试。
