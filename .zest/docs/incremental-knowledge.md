# 稳定事实与页面增量维护

M132 在 M131 页面写作之后加入跨版本记录。新调查可保留稳定事实身份，按来源、静态依赖和关联页面
安排更新。原调查结论与评审不改写；每轮保存新的知识快照。离线验证不代表真实项目理解准确率。

## 一次更新如何推进

打开、切换、任务完成和手动检查仍只检查本地 Git，不自动拉取远程或空闲定时扫描。
新调查冻结 `incremental_contract` 和完整 `incremental_context`，包括基线、来源检查及页面状态。
调查规划收到有容量上限的影响线索；未显示的线索不是已处理项，完整上下文仍保留。

1. **核对来源。** 对旧事实逐条检查目标提交的安全文本。相同 blob 使用原行段；内容移动时只接受
   完整原文唯一匹配，重复匹配不猜测。删除、无法读取和找不到原文分别保留问题。
2. **识别影响。** 组合来源变化、静态导入依赖、显式关联页、失败页及工作区产物变化。
   Python、相对 JS/TS 导入，以及 Java 类、常见 Service/Impl、Mapper XML 提供保守线索。
   全局配置、无法完整处理的依赖及未知代码语言扩大失效范围。
3. **调查并核对新事实。** 继续复用原研究流程和原文评审，不把旧事实直接塞进当前版本的已确认知识。
4. **决定事实关系。** `document_update` 对有问题的旧事实逐项作出确认、替代、撤回或仍无定论的决定，
   并规划受影响旧页与必要新页。肯定性决定必须引用本轮真实核对事实及其完整原句，解释主体、属性和条件。
   本轮未提到、文件删除或缺少材料都不构成撤回依据。
5. **按页写作与发布。** 未受影响页沿用原正文；受影响页执行 Writer 和整页复核。单页失败保留前版，
   人工编辑输出候选，其他页面继续。缺少新证据的问题会阻塞对应旧页更新，不伪装成完成。

`document_update` 判断的是完整新旧断言的关系，规划视图使用断言及来源位置；原文保留在私有快照中，
由具体页面 Writer/Reviewer 读取，不在总规划请求中重复铺开所有原文。
新增模块没有旧事实引用时，本轮新事实仍须归入新页或既有页；没有核对事实覆盖的变更保留覆盖缺口。

当前总页数上限仍为 6，整轮仍共用 32 次物理调用、30 分钟、48000 字符请求上限。
无法容纳的必要内容明确保留为未完成，不通过截断断言、追加预算或重发未知请求绕过。
调查在发送前停止、没有形成计划时，不因执行文档整理而推进全局认知版本。

## 稳定身份与真实版本

稳定事实 ID 使用 `K...`，不再等同于某轮 `run-id:Tn:Fn`。完全相同的已核对断言身份可复用，
语义替代需要明确决定；重复报告只合并完全相同的断言身份，不做模糊语义合并。
替代后保留 ID、增加内容修订号并链接前一修订；历史快照保留原断言，撤回也不删除历史。

| 记录 | 含义 |
| --- | --- |
| verified | 本轮确实核对的事实及其实际调查来源 |
| inherited | 旧事实原文在目标提交仍可定位，保留实际核验版本 |
| needs_review / unresolved | 已受影响或仍缺新证据，不能作为新正文的有效依据 |
| retracted | 有明确新事实依据的撤回，保留原内容与处理决定 |
| 页面 last_verified_commit | 该页最近实际正文复核版本 |
| 页面 evidence_checked_commit | 最近检查来源的版本，不表示正文或全部依赖已重查 |
| 页面 claim_bindings | 实际已发布正文绑定的事实修订号和断言哈希 |

沿用页面不修改正文、文件时间或实际核验版本。关联页可能因关系影响而重新写作，
其旧事实仍保留自己的核验历史；页面复核和事实调查是不同记录。
新正文引用继承事实时，正文末尾也说明原核验版本，不能只在内部状态里区分。

若知识已更新到修订 2，但某页写盘失败，该页仍绑定修订 1，并显示旧版状态。
恢复成功后才切换正文绑定。知识快照不会把旧正文假标为新修订。
已经明确撤回且无新内容的页可归档，保留历史文件，不物理删除团队资料。

## 私有快照与团队清单

私有快照保存在对应认知存储的 `knowledge-snapshots/<run-id>.json`，逐轮保存校验和及父快照引用。
它包含事实来源、状态、修订关系、页面基线和依赖线索。原 SQLite 调查与调用收据继续保留。
当前问答的已核对事实来源仍由认知库按版本筛选；没有把继承标签直接改成当前版本 `auto_reviewed`。

团队共享 `.zest/docs/generated/knowledge.json`，包含稳定身份、断言、来源身份和原文哈希、页面绑定及版本。
不共享原文全文、私有请求/收据、API 配置或本机绝对路径。清单也受安全单文件读取容量限制。

新机器从提交内的清单及对应 Git 原文重建线索。清单即使校验和正确，也不成为模型语义正确或写权限的证明：

- 导入事实标记为 `shared_unverified`，必须由本机的新调查或明确处理决定重新支持。
- 不能凭清单中的文件哈希覆盖团队原文；发生冲突时生成文档候选。
- 原共享清单也保留，新的清单候选位于 `generated/candidates/<run-id>.json`，供人工检查和合并。
- 对应原始提交缺失、来源被阻止或哈希不一致时明确报错；浅克隆不能保证重建成功。

只提交本机已生成且内容匹配记录的文档/清单时，沿用现有按内容识别的零模型检查。
同一 HEAD 也会检查已知生成产物：文件缺失、人工改动或原页面流程未完成时，显示待核对，
不单凭 HEAD 相同宣称全部完成。检查本身不重发历史模型请求。

## 使用与限制

Web 继续使用“检查更新”、`maintenance.resume` 和原初始化恢复入口，无需逐页批准。
页面详情显示本轮发布、沿用、待复核、归档及事实统计。未知请求沿用原收据保护。
旧包没有新增契约时保留旧行为；旧 M131 页面可从本机已核对记录建立首次基线，不修改旧批准包。

静态依赖仅是影响提示，不能穷尽动态导入、Spring 注入、反射、外部服务或业务语义关系。
跨模块判断、事实确认/替代/撤回以及写作质量仍依赖真实模型评测；目前不能据离线流程宣称降低费用或提高准确率。
未核验的团队约定与运行、合并、部署状态继续保持未知。

主要实现：`knowledge_snapshots.py`、`incremental_documents.py`、`incremental_contracts.py`，
接入认知规划、原调用账本、页面发布器、维护检查与 Web 进度。
验证见 `tests/test_incremental_documents.py` 和 `work/m132-validation/`。
