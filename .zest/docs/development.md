# 共享文档模块的使用与开发

## 使用顺序

1. 接入项目，执行 `zest project documents <project-id> --init`。
2. 检查返回的文件、来源清单与冲突；共享文档保存在 `.zest/docs/`。
3. 明确决定提交时，再使用 Git 检查并提交需要共享的文档与忽略规则。
4. 推送后，其他成员同步仓库并接入；各自本地记录保持独立。
5. 通过正常问答或开发建议使用这些文档；新版本内容需要对应 Git 提交。

本模块不自动执行提交、推送、远程同步、调查模型或项目测试命令。
M113 已提供以对话为主的 Web 界面，项目状态可查看工作区文档，包括尚未提交的内容。
连续对话与重启使用见 [Web 说明](conversation-ui.md)；M115 已接通 [项目初始化调查](initialization.md)。

## 实现位置

- `zest/document_layout.py`：共享路径、文档类型与选择性忽略规则。
- `zest/documents.py`：版本化目录、自动文档上下文、显式迁入与来源清单。
- `zest/resources.py`：接入包含共享文档的克隆，保留本地身份与旧存储路由。
- `zest/files.py`、`search.py`、`index.py`、`survey.py`：仅对共享文档开放读取、检索、摸底。
- `zest/qa.py`、`repair_agent.py`：文档参与问答和开发建议，开发的自动文档上下文为只读。
- `zest/repairs.py`：阻止维护原位置的项目文档；`.zest/docs/` 可作为明确修改目标。
- `zest/verification.py`：允许共享文档进入验证快照，布局配置不作为运行文件导出。
- `zest/cli.py`、`web.py`、`web_commands.py`：公开 CLI、只读目录与耐久操作入口。

## 容量与边界

- 文档目录最多 128 个允许文件、4096 个目录项，超量会提示，不能声称完整。
- 单次迁入最多 128 个新文档、4 MiB；按选定提交读取，现有文件冲突不覆盖。
- 允许 Markdown、RST、文本、JSON、YAML；沿用凭据、编码、普通文件及路径校验。
- 符号链接、路径穿越、个人数据库和共享文档以外的 `.zest/` 文件不进入正文读取。
- 问答自动选取最多三份文档，按现有上下文预算收录；这不保证任意大型文档全部进入模型。
- 已接通本地 Git 事件检查与增量维护；完整跨分支、合并和部署状态发现仍未完成。

## 验证

新增验证位于 `tests/test_documents.py` 和 Web 操作测试，包括真实本地裸仓库的推送、克隆、
同步，迁入幂等、来源冲突、本地状态隔离、问答/索引/调查/开发上下文与只读修改范围。
这些测试不使用外部模型或真实远程托管，也不构成模型语义准确性或生产部署验收。
最终运行数量与结果记录在本轮开发日志。
