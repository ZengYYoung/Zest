# 项目范围资料读取与连续调查（M130）

日期：2026-10-23。对应 [OpenWiki 研究方案](openwiki-research-2026-10-23.md) 的阶段 A。

## 当前行为

Web 的“接入并初始化”和“初始化项目”仍是开始入口。新初始化、补全和增量调查会冻结选定
commit 的完整允许文件目录；初始摸底提供的文件不再是项目读取权限的上限。
范围内检索、分页列举、读取相关文件和继续读取后续行段，由后台调查直接执行。
未提交修改仍不包含在本轮资料内，运行记录继续显示实际观察版本。

文件目录按现有路径、扩展名与普通文件规则建立；尚未读过的文件只有路径和 Git blob 身份，
实际读取时再检查内容、计算 SHA-256 并保存原文证据。文件原文不再要求全部预先存入资料包。
路径可能是可读候选，但实际内容若含凭据、非 UTF-8、二进制或超过单文件容量，读取会明确返回原因。
默认单文件 256 KiB 的已有限制仍保留；旧的摸底 200 文件、4 MiB 限制只约束起始采样。

项目检索按文件流式处理固定版本资料，匹配结果仍须经过 read 才能引用；搜索内存缓存最多 32 个文件。
模型每轮只收到当前目录窗口和最近原文，并有已读证据定位索引；需要旧原文时可以再次读取，沿用原 R 身份。
所有实际读取结果仍保存在调查 checkpoint/成果中，模型窗口省略内容不表示其已解决或不存在。

## 连续执行与容量

- 单次请求超过内部默认长度时，新版项目调查不再转入字符扩展审批。
- 发送前按实际 SDK 请求长度调整可选资料列表，保留完整条目，不截断原文或改写任务目标。
- 调查累积原文不再因达到旧证据警戒长度而被强迫立即结束；按窗口继续补读。
- 新项目调查单任务最多 8 轮、32 次工具动作；整轮仍最多 32 次物理模型调用、30 分钟。
- 请求仍最多 48000 字符；不能分开的必要原文或任务若仍超限，会保存明确错误，不伪报成功或外发。
- 核对请求保留其必需发现和证据，沿用超长批次拆分；不能为了满足长度丢掉必需证据。

本阶段解决资料范围和上下文组织，尚未引入按页面的独立写作任务或可配置项目总预算。
单轮结束也不表示已穷尽项目；预算耗尽或缺少证据时仍保留真实缺口。

## 项目持续授权

新开启设置保存 v2 授权，绑定项目、根目录、模型目标、资料访问策略版本、文档目标与总预算。
内部 Prompt、核对实现和同一模型目标下的 API Key 更新不再单独使持续授权失效。
每个实际调查仍保存当时的指令、目录、预算、请求正文、来源版本与调用收据。

数据去向、模型目标或访问权限发生变化时需要重新确认。关闭开关停止新的自动工作；
已经批准的一轮继续在自身预算内完成。调用结果未知、明确拒绝或预算耗尽不自动重放。
代码执行、源码修改、提交、推送和部署仍不属于文档调查权限。

旧 v1 授权保持旧范围，新规则不会悄悄扩大旧授权。设置会说明旧范围，重新开启设置或
显式开始初始化可启用新范围；旧调查及已经发送的请求不重建、不追加权限、不改写记录。
原生按包准备/批准入口继续兼容旧流程。

## 增量与补查兼容

新版本增量仍复用现有维护流程；变化路径映射到完整项目目录，避免后续目录的源码被误标为包外。
未预读文件的证据以 commit/blob 与读取时 SHA-256 关联，供项目上下文、变化比较和补查使用。
需要核对历史原文时，通过原 commit 重新读取该来源，不能用当前工作区内容替换。

M130 本身没有实现跨版本事实自动继承、每页独立基线或工程文档 Writer。
后续 M131 已接入 [主题规划、页面写作与恢复](engineering-documents.md)，旧调查仍使用原发布器。
后续 M132 的跨版本事实记录、局部更新与独立页面基线见 [增量维护](incremental-knowledge.md)。BlindBox 的旧阻塞任务没有因升级而自动重新执行。

## 验证与边界

新增 `tests/test_project_source_access.py`，通过临时 Git 仓库与明确的离线模型验证：
超过 200 文件及合计 4 MiB 的目录访问、后续文件检索与读取、工作区隔离、敏感内容和链接拒绝、
上下文窗口与证据保留、长规划请求分批和回执复用、稳定授权、完整初始化以及后续增量定位。
另有旧审批、初始化、补查、维护、上下文与资源隔离回归。最终数量与结果见开发日志。

这些是程序流程和状态验证，没有发起真实外部模型请求；尚未证明真实项目文档的理解准确性或阅读质量。
