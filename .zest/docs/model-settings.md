# DeepSeek 密钥配置（M114）

当前 Web 设置只需填写 DeepSeek API Key，不要求填写 Base URL、选择提供商或读取模型列表。
内置 `deepseek-flash`、官方地址 `https://api.deepseek.com`；结构化输出仍通过现有 `/beta/chat/completions`
和严格工具 schema 调用。模型名和基础地址依据 [DeepSeek 官方说明](https://api-docs.deepseek.com/zh-cn/)，
不是通过当前用户密钥在线发现的。

## 使用

更新代码后先重启原来的 Web 服务，在原终端按 Ctrl+C，再在 Zest 项目根目录运行：

```bash
uv run zest web serve --port 8000
```

打开 `http://127.0.0.1:8000`，右上角设置 → DeepSeek API Key → 保存密钥。
无需修改 `.env`，无需重启即可供之后的对话和后台任务读取。
已有 `.env` 配置在未保存网页配置时继续兼容；网页配置保存后优先使用固定的 DeepSeek 目标。
更换密钥时填写新值并保存，不会将旧密钥回填到输入框。

保存是本地操作，不校验账号余额、模型可用性，也不会发送任何模型请求。
“已配置 · 待实测”与“最近连接测试通过”分开显示。
可展开“连接测试（可选）”，准备、审阅并执行固定加法示例的真实调用；不包含项目源码，最多一次，不自动重试。
也可以直接返回对话提问，按现有流程确认本轮资料后获得真实模型回答。
关闭服务在运行它的终端按 Ctrl+C。

## 保存位置与接口

- `POST /api/model/settings`，JSON 仅接受 `{"api_key": "本机填写的值"}`，返回无密钥的配置状态。
- `GET /api/model` 返回配置状态和历史测试，始终不返回密钥、不调用模型。
- 密钥以明文保存在所选本地状态目录的 `model-settings.json` 中，文件权限 `0600`，原子替换。
  默认是 Zest 的 `.zest/model-settings.json`；不是共享文档，不随 `.zest/docs/` 提交。
- 保存绕过耐久操作队列，不在操作参数、操作收据、localStorage 或共享文档中保存密钥。
- Web 请求、操作 worker、CLI 和项目调查 worker 使用对应目录配置；传给子进程的仅是目录位置。
- 每次保存产生新配置版本。旧连接测试不再证明当前密钥可用，旧的待批准连接测试需要重新准备。
- 损坏的本机配置会报错，不静默回退到其他密钥；重新保存可以修复。原 `.env` 文件不会被修改。

## 验证范围

离线测试覆盖保存、刷新/重建应用、权限、不回显、非法参数与来源拦截、多实例隔离、旧环境配置兼容、
后台配置读取、子进程目录继承、密钥更换导致历史测试失效、符号链接/损坏文件拒绝。
连续对话经耐久操作、LangGraph 和实际 LangChain 适配器走到 MockTransport，检查模型、URL 和鉴权使用新配置，
检查持久操作收据不包含密钥。这些验证不使用外部模型。
浏览器使用隔离临时目录及无效测试值验证单字段输入、保存清空、刷新后配置保留。
截图保存在忽略目录 `work/web-smoke-m114/`；没有替换用户实际密钥或调用真实模型。
