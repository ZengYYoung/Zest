# Zest

**你的专属私人项目管家。**

一个运行在本机的项目助手：理解 Git 仓库、结合来源回答问题，并在代码变化后持续维护可读的软件工程文档。

[English](README.md) · [简体中文](README.zh-CN.md) · [发行版本](https://github.com/ZengYYoung/Zest/releases) · [反馈问题](https://github.com/ZengYYoung/Zest/issues)

**首个发行版：`v0.1.0-alpha.1`，面向本机单人试用的 Alpha。** 当前仅支持 DeepSeek。本次为源码发行，不包含桌面安装包、托管服务或生产级多人协作。

## 为什么使用 Zest？

每次开始对话，不应都从零解释整个项目。Zest 将项目文档、已核对发现、源码引用和对话历史保存在一起，帮助你持续回答这些问题：

- 一个请求经过哪些模块，它们如何协作？
- 某个接口如何使用，有哪些约束？
- 相对上次调查改了什么，哪些文档需要更新？

Web 是主要使用入口。主界面围绕连续对话展开，设置、项目文档和维护详情按需打开。

## 功能概览

| 能力 | 本版已具备的内容 |
| --- | --- |
| 项目工作区 | 接入本机 Git 项目，按项目浏览对话；从列表移除项目时保留磁盘文件。 |
| 自动初始化 | 建立 `.zest/`、整理已有资料、索引已提交源码、调查项目，并生成按主题组织的工程文档。 |
| 项目问答 | 结合项目知识、源码片段和前文用自然语言回答，支持查看来源。 |
| 工程文档生成 | 按页规划、撰写、复核和保存；保留人工修改，冲突时提供候选版本。 |
| 增量维护 | 打开/切换项目、任务完成或手动操作时检查本地 Git，调查变化并更新相关知识与页面。 |
| 可见的执行过程 | 展示活动动画、阶段、等待时间、页面计数及明确的结束或失败状态，保留回执以便恢复。 |
| 文档共享与个人状态分离 | 通过 Git 共享选定的 `.zest/docs/` 文档，对话、数据库、密钥和执行状态留在本机。 |

CLI 另外提供调查、修复建议、候选修改、Docker 容器验证和版本操作等能力。**“澄清需求 → 开发 → 测试 → 交付”的完整流程尚未在主对话中贯通。**

## Quickstart

### 环境要求

- **Git**；源码调查需要一个至少已有一次提交的本机仓库。
- **Python 3.11+** 与 [uv](https://docs.astral.sh/uv/getting-started/installation/)。
- **Node.js 22.12+** 与 npm，用于构建 Web 前端。
- 能访问配置模型的 **DeepSeek API Key**；模型调用会产生提供商费用。

当前主要在 macOS 上试用。原生文件夹选择器仅支持 macOS；其他 Unix 环境可以手动填写路径，但尚未经过同等发行验收。部分后端使用 Unix 文件锁，原生 Windows 支持尚未验证。普通项目问答无需 Docker，只有部分高级验证流程需要它。

### 1. 获取版本并安装依赖

```bash
git clone --branch v0.1.0-alpha.1 https://github.com/ZengYYoung/Zest.git
cd Zest

uv sync --locked --extra ai --extra web
npm --prefix frontend ci
npm --prefix frontend run build
```

### 2. 启动本机工作区

在 Zest 仓库目录中执行，并保持终端运行：

```bash
uv run --locked --extra ai --extra web zest web serve --port 8000
```

打开 **[http://127.0.0.1:8000](http://127.0.0.1:8000)**。无需注册、登录或 Web token；在终端按 `Ctrl+C` 停止服务。

### 3. 配置模型并接入项目

1. 打开右上角 **设置**，填写 DeepSeek API Key 并保存。保存只写入本机；可选的连接测试会进行一次真实模型调用。
2. 点击左侧 **项目** 旁的 **+**，选择本机 Git 仓库或填写根目录绝对路径。
3. 点击 **接入并初始化**。这会为该项目启用自动项目理解，将允许访问的已提交源码与文档发送给 DeepSeek，完成调查与文档生成。
4. 查看执行进度，然后直接提问；在 **项目状态** 中阅读文档、检查更新或核对未完成内容。

调查和明确开启的文档轮次，每轮上限为 **32 次物理模型调用、30 分钟**。这不是固定费用承诺；资料、时间或调用容量不足时，部分页面可能保持未完成。开启新文档轮次需要显式操作，并可能产生额外费用。

当前界面文案为中文，本次发行提供中英文使用说明。

## `.zest` 机制

每个接入项目都会建立自己的资源目录：

```text
your-project/
├── src/                         # 原有业务代码保留原位
└── .zest/
    ├── workspace.json           # 本机项目身份与存储路由
    ├── AGENTS.md                # 自动生成的管理导航
    ├── .gitignore               # 共享文档与本地状态的忽略规则
    ├── docs/                    # 可以按需随 Git 共享的项目文档
    │   ├── index.md
    │   ├── imported/            # 迁入资料及来源记录
    │   ├── initialization/      # 按主题生成的页面、冲突候选
    │   └── generated/           # 可共享的项目知识清单
    └── state/                   # 按使用创建的个人本地状态
        ├── state.sqlite3
        ├── conversations.sqlite3
        ├── cognition.sqlite3
        ├── index.sqlite3
        └── …                    # 任务、快照、检查点、锁与回执
```

- **SQLite 是磁盘文件**，不需要独立启动数据库服务。不同用途的记录分布在多个数据库中，并非只有一个总数据库。
- **文档与个人状态分别管理**：Zest 维护 `.zest/docs/` 下的项目文档；既有 README/docs 可以读取、迁入，原文件保留。生成文档不会自动提交或推送。
- **团队共享需要 Git 操作**：检查并提交需要共享的文档和忽略规则，推送后由其他成员同步。共享的是已提交文档，不是个人对话或 SQLite 文件；项目自定义忽略规则仍可能阻止文档被跟踪。
- **目前尚未全部收敛到各项目内部**：服务使用的项目列表、网页操作回执和模型设置，保存在所选服务状态目录中，默认是 `<启动 Zest 的目录>/.zest/`。旧记录可能保留在原位置，由 `workspace.json` 引用。
- **人工修改保留**：发现冲突时输出候选，不静默覆盖原文。因此正文可以已经完成，而新目录仍作为候选等待查看。
- **删除项目可恢复**：删除按钮只隐藏当前登记条目，源码、`.zest/` 和历史记录保留；重新接入同一目录可恢复原身份，已启动的后台任务不会因此取消。

需要自定义服务状态目录时，将全局参数放在子命令前：

```bash
uv run --locked --extra ai --extra web zest --state-dir /absolute/path/to/zest-state web serve --port 8000
```

这会改变项目登记与配置位置，**不会自动搬迁旧数据库**。已有项目仍可能引用原存储，完整备份可能需要同时包含项目资源与原服务状态目录。

## 模型支持与数据处理

| 配置项 | 本版支持情况 |
| --- | --- |
| 模型提供商 | 仅 DeepSeek |
| Web 内置模型 | `deepseek-flash` |
| 官方基础地址 | `https://api.deepseek.com` |
| 结构化输出接口 | `https://api.deepseek.com/beta/chat/completions` |
| 推荐配置方式 | 在 Web 设置中填写 API Key |
| 可选 CLI 配置 | 参考 [`.env.example`](.env.example)；已保存的 Web 配置优先 |

本版不支持其他提供商、本地模型或任意 OpenAI 兼容接口。内置模型只是应用预设，不代表已验证每个账号的模型权限与可用性。

执行模型任务时，相关源码片段、项目文档及对话上下文会发送至 DeepSeek。API Key 仅留在服务端，Web 设置将其以**未加密明文**保存到服务状态目录的 `model-settings.json`，使用仅所有者可读写的文件权限；不会回传浏览器或放入共享文档。本地调查与操作记录也可能包含项目原文，应按私有资料管理这些状态目录。

服务仅绑定 `127.0.0.1`，检查本地 Host/Origin，面向本机单人使用；尚无生产级认证与远程协作层。详情见 [模型配置说明](.zest/docs/model-settings.md)。

## 持续维护流程

```text
固定 Git 提交 → 源码检索 → 项目调查与核对
                               ↓
项目问答 ← 已核对知识 ← 主题页面与来源引用
                               ↑
             本地 Git 变化 → 增量维护
```

调查读取固定 Git 提交。文档阅读器则可以展示当前工作区文件，包括尚未提交的文档修改，两者会区分。Zest 不自动拉取远程更新，也不会在空闲时持续扫描；其他成员的变化需要先同步到本机。

恢复流程尽量复用已保存结果和完成页面，不自动重发执行结果未知的请求。缺少依据或未通过复核的页面保持未完成，知识缺口继续保留。“已发布”“已核对”是工作流状态，不代表模型已准确理解整个项目。

## 当前边界与后续方向

本版用于本机试用。已有一轮真实 BlindBox 文档生成完成 **5/5 页、27 次模型调用**，同时保留人工编辑的原目录；这验证了该范围的有界生成流程，不代表通用文档准确性、大仓库稳定性或部署效果均已验收。

下一步重点是项目问答质量评估、连续增量维护实测和稳定试用基线。服务器部署、基于 PostgreSQL 的多人协作、完整跨分支/合并/部署状态追踪、更多模型提供商，以及端到端自主开发，仍属于后续方向。
