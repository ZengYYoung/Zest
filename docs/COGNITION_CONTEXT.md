# 认知上下文与单次字符扩展

日期：2026-10-15。M038 在既有固定版本调查上补齐证据组织、报告收束和适度超限批准，不扩大资料或执行权限。

## 保留证据并交付报告

每次 MCP 读取的完整 text、逐行 lines、固定版本/文件哈希与物理行段继续保存到任务 checkpoint 和结果。给模型的视图仅保留一份原文及行段，去掉重复的 lines 文本；完全相同的读取复用 R 编号，历史动作记录仍全部保留。不同或部分重叠的行段不会被当成同一证据，也不截短原文以凑额度。

工具上下文超过内部 22000 字符预警时（M040 从 18000 调高），先去掉旧定位提示；若原文仍超预警，下一轮改为报告，不再直接交空发现。四轮总额度中，最后一轮保留给报告：project_report 绑定仅允许最终报告的 Pydantic 类型，不能再请求工具。不增加模型总调用数或工具权限。

每轮最多四个动作，保留末轮报告后最多执行三个工具轮，即最多十二个动作；原十六动作上限继续作为防线，不额外增加第五轮。

报告请求不再携带旧检索位置，保留已读原文。M046 起同时保留完整批准包的精简 ID/路径目录，将 read_source_ids 单列，避免把包内未读误当包外；完整目录仍计入实际请求预算。核对请求使用唯一原文表和每条发现的 evidence_ids，重复证明只发送一次；持久 finding 仍保留原来的完整证据。报告可以诚实返回 partial 与未知，结构正确不证明语义正确。[资料需求分类](COGNITION_MATERIAL_REQUESTS.md)

M048 进一步将任务的空读取视图放入 metadata_observations，非空正文和其他工具结果仍在 tool_results；两路都保留至报告轮、一起计入字符预警/实际请求。原始工具历史与正文证据不移动或删改，空观察不生成 R 编号，也不作为模型 findings；见 [元数据边界](COGNITION_REPORT_RECEIPT.md)。

M040 扩大单次阅读与报告容量，并对超过 48000 字符、确定尚未外发的核对候选减小批次；单条仍过大则保留缺口。等待字符批准、已收到或结果未知的请求不因此重发。[容量与规模提示](COGNITION_CAPACITY.md)

## 统计完整请求体

通过与实际发送相同的 LangChain/SDK 适配器，在本地内存传输中编译完整请求；该传输只捕获请求并立即停止，不访问模型网络，不生成模型回答。编译前替换密钥、关闭 tracing，不保存认证头。

计数为实际 JSON 请求体的 Unicode 字符数，包含系统消息、用户资料、工具 schema、输出预算及模型参数；不是仅统计 payload、UTF-8 字节数或估算 token。实际 URL、原始请求体和 SHA-256 一并保存。发送前核对 URL 与原始请求体，变化则在传输前阻止，记为 not_sent；不自动重发。

| 完整请求体大小 | 行为 |
| --- | --- |
| ≤ 32000 | 沿原固定工作流批准执行 |
| 32001–48000 | 保存完整请求，暂停等待本次字符扩展批准 |
| > 48000 | 不提供扩展放行；调查先重组为报告、去掉定位提示，仍过大则保留证据与缺口，需拆分或缩小调查 |

每个实际调用在扣预算/记 pending 的同一事务保存编译请求。等待扩展的请求尚未外发，不占调用次数。扩展绑定 run、任务、轮次、原完整包哈希、实际模型目标、完整请求体和本次上限；不能批准一个大小后用于另一个请求。损坏、目标/指令/schema 漂移或未知旧调用均不能借扩展批准继续发送。

原 32 次调用、4 轮、固定目标与 1800 秒软时间预算继续有效，等待时间仍计入该既有时间预算；字符扩展不延长它。扩包、改模型、修改、测试和发布仍需各自批准。

## 审阅、批准与拒绝

终端“项目认知”显示待批准的任务、字符数和超出比例；worker 停下后，“审阅超限请求”打开完整记录。勾选明确同意后才能批准；Escape/返回不作决定。并行任务可以各自形成待批准请求，所有当前待决请求均决定后才重新排队；已完成的调查保留，依赖任务继续等待。

CLI 也可审阅并按精确哈希逐个决定：

```bash
zest cognition context-preview <run-id>
zest cognition context-approve <run-id> <actor> <sequence> --request-sha256 <本次请求哈希>
zest cognition context-reject <run-id> <actor> <sequence> --request-sha256 <本次请求哈希>
```

两个决定命令都可加 --no-start，仅保存决定；全部决定后由 worker 继续。拒绝的请求不发送，关联调查以 partial 保留原文与缺口，其余可执行任务继续。规划或核对请求被拒绝时，工作流保留已有成果并以 partial 收束。

recover 不能代替扩展批准。重启后从持久请求和 checkpoint 继续，已保存模型响应按身份复用；pending/uncertain/invalid 或没有有效结果的旧调用仍禁止重发。若在保存待批准请求后、更新界面阶段前进程退出，原记录仍可审阅；决定操作取得 run 锁后重新核对状态。

Web 仅展示等待状态、大小和终端/CLI 处理提示，没有新增写入接口。旧数据库无需改写即可只读查看，旧批准不能用于变化后的契约。
