# 项目认知工作流

日期：2026-10-14。首轮实现为固定 Git 版本的自主静态调查，适用于已登记的开发/导入项目。

## 开始使用

```bash
uv sync --extra ai --extra mcp --extra tui --extra web
# 在运行目录的 .env 配好模型；不把密钥提交到 Git
uv run zest project import /absolute/path/to/project
uv run zest ui
```

工作台顶部“项目认知”或 Ctrl+U → 新建调查 → 审阅资料包 → 勾选并批准。无需先知道该看哪些文件。准备只做本地摸底和资料保存；批准后才启动独立 worker 和模型工作流。返回主对话或退出工作台不会取消后台调查。

也可使用子命令，全部支持放在命令前面的 `--state-dir /absolute/path/to/state`：

```bash
zest cognition create <project-id>
zest cognition create <project-id> --survey-id <已有摸底记录-id>
zest cognition preview <run-id>
zest cognition approve <run-id> --approval-sha256 <完整预览中的哈希>
zest cognition watch <run-id>
zest cognition show <run-id> --format text
zest cognition dossier <run-id> --format text > project-dossier.md
zest cognition list <project-id>
```

`preview` 包含完整允许文件全文、同版本共享认知、规划/调查/报告/核对四个工作指令、完整结构化输出 schema、实际模型目标和预算。批准哈希覆盖完整包，不仅覆盖清单。包内可自主查找，包外来源不能通过任意路径访问；扩大范围需新建工作流再批准。

`approve` 默认启动后台 worker；`--no-start` 只入队，可另运行 `zest cognition worker`。worker 处理队列，默认空闲 30 秒后退出；`--once` 处理一项后退出。它是独立本地进程，不是永久后台服务。修改、测试、网络工具、发布不在调查批准内。

## 流程与职责

```text
本地摸底 → 完整资料包 → 人批准 → 主 Agent 规划
                                       ↓
                          按任务创建 Agent，最多两个并行
                              MCP 检索/原文读取循环
                                       ↓
                          原文引用校验 → 独立语义核对
                                       ↓
                          有限补查 → 六部分档案 / 缺口
                                       ↓
                       同版本共享认知供问答和后续任务检索
```

主协调图和每个子任务均有独立 LangGraph SQLite checkpoint；任务库保存状态与请求账本。LangChain 处理模型请求，MCP 工具仅使用保存的授权包，不重读当前工作区。资料中的提示不能改变程序权限。

内置工作指令与严格契约在 `zest/cognition_contracts.py`。规划用有预算的清单和文档形成 overview/tasks/gaps；任务包含目标、理由、线索、成果、完成标准、优先级/依赖。Agent 可查找包内非线索文件，已完成前置任务报告供依赖任务参考。

响应绑定 [Pydantic 输出模型](STRUCTURED_OUTPUTS.md)，统一经 `with_structured_output` 原生 strict 工具调用生成；调查的动作/报告采用互斥变体，末轮或证据预警使用仅允许报告的独立类型。官方 DeepSeek 根接口在预览前显式解析为 `/beta`，输出契约变化阻止旧批准执行。结构正确仍须原文与业务规则核对。

词法 RAG 按 40 行、30 行步长分块，TF-IDF 余弦排序；检索只返回位置，必须实际 read 才能引用 R 编号原文。它不是语义向量检索。符号工具提供 Python AST 声明位置，不执行源码。

报告保留 observed/inferred、原文和未知项。核对 Agent 检查证据支持，参考其他发现核对明显矛盾；仅 observed 且受支持的记录可 auto_reviewed。Agent 一致不能证明事实。被否定的观察最多追加两个补查任务，推测保持待核实，不无限循环。

M042 起空读取保留元数据观察但不分配 R 正文编号。报告通过完整结构校验后逐条接收：无效候选连同原报告/原因独立留痕，其他候选保持原编号继续语义核对；有拒收即 partial。CLI、终端、档案及只读 Web 显示拒收原因，详见 [报告接收与空文件观察](COGNITION_REPORT_RECEIPT.md)。

M048 起任务输入将成功读取的空文件/空窗口分到 metadata_observations，非空正文及其他工具结果留在 tool_results。原始读取/checkpoint、非空 R 身份与全部元数据保留，共同计入请求和预警预算。程序已记录的元数据不在 findings 重复交付；无正文发现继续拒绝空引用，相关成因/意图未知仍可说明。当前只有离线验证，不代表模型线上行为已改善。

随后 M049 经具体批准执行一条真实报告请求，但供应商返回的工具参数末尾多一个 `}`，strict 请求仍被 SDK 判为无效。原始收据保存后停止，未进入引用/分类接收，线上元数据表达效果仍未知；没有修复或重发，见 [本次复测](COGNITION_ACCEPTANCE_M048.md)。

M051 在单独批准的 LangSmith 诊断中使用相同请求，本次原生结构、引用及包内资料分类通过，11 个追踪步骤云端核对一致；这是单个报告轮结果，未重评完整项目理解质量。M052 按用户选择，以预算内一次已知格式失败补试完成该问题的工程收尾，不再继续自动试跑或修改 schema，见 [诊断结果](COGNITION_ACCEPTANCE_LANGSMITH.md) 与 [补试机制](COGNITION_RETRIES.md)。

M044 起报告发现数量约六条仅为软建议，不再作为整体拒收条件；仍受完整响应 32000 字符、各用途输出 token 和总调用预算控制，每条独立校验，不截断原报告或放行坏引用。原八条响应已通过本地接收回放，原真实成绩保留。

M046 起任务/报告保留完整批准文件的精简目录，read_source_ids 另列已读窗口来源（含空观察），两者均不是正文证据。模型输出具名 material_requests，由本地目录核对并派生包内待补读/包外需求；ID/路径错误单独留痕、有效发现继续核对。这里只记录待办，不自动补读或增加预算；旧自由文本只读显示为未分类，详见 [资料需求分类](COGNITION_MATERIAL_REQUESTS.md)。新契约不能复用旧批准。随后一次真实复测的五项分类正确，但一条元数据候选被隔离，全部判据未通过，见 [M047 记录](COGNITION_ACCEPTANCE_M046.md)。

## 默认预算

M053 增加 `cognition refresh-preview <project-id>` 与终端“版本更新”：只读比较当前选定 commit 和既有认知基线，列出变更/未变/无法核对的证据及未覆盖变更，不调用模型或修改知识。M054 的 `cognition refresh-create <project-id>` 可将变化与旧线索冻结到新版本待批准资料包，单独批准后复用现有规划/调查/核对；准备不外发，旧认知不迁移，真实增量效果仍待验收，见 [增量调查](COGNITION_REFRESH.md)。

| 预算 | 上限 |
| --- | --- |
| 初始任务 / 总任务 | 4 / 6，最多两个并行 |
| 每任务模型轮次 / 工具动作 | 4 / 16，每轮至多四个动作 |
| 整轮模型请求 | 32，规划、调查、核对共用原子计数 |
| 已收到的格式失败 | 每个逻辑请求最多补试 1 次，同样计入上述 32 次，不增加总预算 |
| 执行时间 | 1800 秒，新请求前检查；不是正在执行动作的硬终止 |
| 完整请求体 / 响应 | 默认 32000 字符；适度超限可逐次批准至 48000；保留报告轮 max_tokens=8192，其余 4096 |
| 请求超时 | 配置 1–120 秒，不自动重试 |
| 本地采集 | 沿用摸底 200 文件尝试、4 MiB 文本和树/时间预算 |
| 完整授权包 | 16 MiB JSON，包含共享认知 |
| 检索分块 / 结果 | 8000 块 / 12 个位置，包尾部可能未覆盖 |
| 工具原文 | 每次最多 400 行及 3000 字符，默认 120 行，不截半行 |

M040 取消规划来源 6/8 个及报告证据两条的额外数量限制，按实际可见目录/已读原文校验有效且唯一的身份。目录、预读与报告容量扩大；达到 200 来源或摸底/目录不完整时提示先确认本轮范围，详细数值与授权边界见 [资料与报告容量](COGNITION_CAPACITY.md)。

超预算、依赖未完成或缺资料时保留部分成果与原因；包外需求显示待扩展授权。静态档案不执行测试，不把配置声明写成运行事实。

## 历史、恢复与核对

```bash
zest cognition show <run-id> --calls
zest cognition recover <run-id>
zest cognition invalidate <run-id> <finding-id> --reason '需要重新核实'
zest cognition reject <run-id>
```

查看不会调用模型或创建空状态库。项目内最近 100 项可浏览，更早记录按完整 UUID 打开。`show --calls` 展示逐次 payload/hash/状态/响应及可用的安全原始收据、usage 和供应商模型名，属于本地私有资料；旧记录没有的指标保持未知。

M038 起还保存实际完整请求体、URL、字符数和正文 SHA-256。适度超限先暂停为 awaiting_context_approval，审阅该任务/轮次完整请求后单独批准；不扣尚未外发的调用，不扩大资料/执行/时间预算。终端有“审阅超限请求”，CLI 有 context-preview/context-approve/context-reject；详细边界见 [认知上下文与单次扩展](COGNITION_CONTEXT.md)。

请求先记 pending 并扣预算，响应收据与解析分类在同一事务落库，再推进 checkpoint。响应已保存而节点未完成时，显式 recover 可复用同身份响应。M052 起，完整响应已收到但 JSON/类型不符合契约时，可依据新包中的 max_format_retries=1 在总预算内补试一次，原请求逐字不变、每次收据独立保存。补试用完的 invalid 不再发送；pending/uncertain 或无有效结果的请求不能重发：服务端可能已处理或计费。活动 worker/同 run 锁阻止重复执行和并发恢复。详见 [格式补试与恢复](COGNITION_RETRIES.md)。

状态：awaiting_approval → queued → planning → investigating → reviewing → completed/partial；错误为 failed，未知调用为 pending_execution。worker 消失时界面显示退出，不冒充仍在执行。completed 仅表示任务完成、六部分有经核对发现且计划无剩余缺口，不是完整理解证明。

新接入项目的记录存于各项目 `.zest/state/` 内的独立数据库/文件，数据库创建权限 0600；`.zest/.gitignore` 忽略全部资源，不改变原生文件。旧记录按原位置/批准哈希兼容，worker 账本、锁和 checkpoint 跟随记录所属位置，见 [项目资源](PROJECT_RESOURCES.md)。授权哈希用于身份与损坏检查，不是防本地管理员篡改的签名。模型密钥只在执行时读取，不保存到包或请求记录；主图、子图、适配器关闭第三方自动 tracing。

## 支持后续维护

问答和修改建议按问题检索最多三条同 commit 的 auto_reviewed 认知，附原文证明和核对意见，纳入各自的新请求批准。推测、失效和跨版本记录不进入上下文。调用前再次核对身份/状态；旧来源失效会阻止旧预览执行。

新认知工作流也可纳入共享知识，但仍须读原文支撑新发现。任务记忆与共享知识分别保存；原 KnowledgeStore 的人确认记录保持 confirmed。

后台运行时问答可用。修改建议涉及活跃调查的起始文件/已返回证据时，等待关联任务核对后重新准备；仅检查文件交集，不是完整语义依赖分析。间接关联仍需读源码、审阅修改和独立验证。

Web 的“项目认知”只读列表/详情展示阶段、调用数、任务、六部分发现和原文。GET `/api/projects/{id}/cognition`、`/api/cognition/{id}`、`/api/cognition/{id}/dossier` 继承本地 Bearer 认证与 no-store。Web 不能创建、批准、启动 worker 或修改知识。

首轮工作流未包含生产日志、完整 Git 历史、自动增量刷新或向量检索。后续分别设计，不把离线夹具输出作为真实项目理解效果。首个真实样本调查已另行批准并执行，但未通过：响应字段契约和证据上下文收束问题导致没有自动核对成果，见 [真实验收结果](COGNITION_ACCEPTANCE_RESULTS.md)。

小规模真实模型验收方案与人工评分模板见 [认知验收方案](COGNITION_ACCEPTANCE.md)。样本与评分门槛已确认，首次批准只适用于当次固定包、模型目标、指令和预算；修正后的真实复测需重新明确批准。

## 字符超限的有限扩展

用户于 2026-10-14 确认：单次完整请求默认 32000 字符；超出不超过 50%（最高 48000）时暂停，展示实际字符数、默认上限、超出比例和完整请求，明确批准后才放行。批准绑定具体任务、请求哈希与本次扩展范围，记录独立留存；超过 48000 先调整上下文组织或拆分调查。

内部证据额度作为提前收束的预警，完整原文与引用身份继续保存；模型可见上下文去除 text/lines 的重复表达。字符预算不是模型 token 上限，扩展不增加获准资料、工具权限或总请求次数，未知请求不能借此重发。

以上规则已在 M038 实现并离线验证；计数覆盖实际 JSON 请求体中的系统消息、工具 schema 和所有参数，发送前再核对原始正文与 URL。末轮保留报告机会，完全相同的读取复用引用。旧 run/批准包不修改；真实复测须审阅新预览并另行批准，参见 [详细实现与边界](COGNITION_CONTEXT.md)。
