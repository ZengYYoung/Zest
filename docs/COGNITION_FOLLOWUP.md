# 同版本定向调查包

M062。把管理总览中的一条未解决发现准备成独立、待批准的定向调查，处理同一 commit 下的核对或补查需求。准备过程不会调用模型，原发现、核对意见、后续行动与旧调用账本保持原样。

## 使用

```bash
zest project context <project-id> --format text
zest cognition followup-create <source-run-id> <finding-id> --format text --progress
zest cognition preview <new-run-id>
# 审阅完整新包后，另行决定是否批准；批准才会启动后台 worker
zest cognition approve <new-run-id> --approval-sha256 <new-package-sha256>
zest cognition watch <new-run-id>
```

CLI/MCP 管理总览的合格行动提供 `prepare_command` 参数数组；命令使用同一登记目录，查询本身不执行命令。保存来源身份不匹配的行动继续提示先查看原记录，不提供准备建议。prepare 还会重新核对保存正文、物理行段与原固定包，不把管理总览的元数据检查当完整原文证明。

只接受当前选定 commit 的 completed/partial 调查，以及其中 observed 且 pending_review/needs_investigation 的发现。推测、已核对、已失效、活跃/失败调查和历史版本均不冒充本入口的同版本目标；版本变化继续使用 [增量调查](COGNITION_REFRESH.md)。源调查缺少登记、原文/引用不匹配或冲突定位损坏时停止，先检查原记录。

## 冻结范围与身份

新包重新收集固定 commit 的完整安全资料，不缩成原任务的起始文件或只有被引用的片段。采集继续受既有文件、大小、凭据、编码、目录与摸底预算约束；允许范围以完整新批准包为准，不声称收录整个项目。未提交内容排除。原文件不复制到新的原生文档目录，必要审计正文保存在原有项目资源布局中。

`envelope.followup_context` 包含项目/commit、源 run/批准包哈希/状态/停止原因、选定发现的完整原断言、原状态和核对明细、关联冲突链及明确定位的任务未知项、各项身份哈希、所需来源在新目录中的位置、唯一目标和完成标准。冲突链按明确引用关系遍历，保留循环两侧，不做模型语义合并；来源身份或关联记录缺失不会悄悄忽略。过大上下文按既有完整请求预算停止或等待精确扩展，不丢弃部分冲突后发送。

旧正文编号、旧 citations 与旧任务 spec 不作为新证据或任务继承。旧结论和核对明细只是待核实线索，即使关联项曾 auto_reviewed 也不是本轮证据。定向包不自动携带已有共享认知，原知识本身不被删除/失效；所有新发现仍需本次实际 read 的非空原文。

准备完成前再次检查选定版本，移动则停止创建认知工作流，已保存摸底可保留。每次物理请求（含获准格式补试）、复用保存响应以及最终收束前，重新比对选定发现、关联冲突链/未知项和源 run 的完整身份；内容、核对意见、状态或源批准包发生变化时要求重新准备。与本问题无引用关联的其他发现变化不会自动扩大本次依赖集合。各存储分别读取快照，不引入跨库全局事务。

准备后的分支移动不偷换已冻结的 commit，后续只调查获批版本。新 run、新资料/指令/Schema/模型目标和新预算须独立审阅批准，不能沿用 M058 或其他已消费许可。旧请求、结果未知请求和旧审批不复制、不恢复或重发。

## 定向规划与执行

规划用途为 `project_followup_plan`，具名 Pydantic `FollowupPlanResponse` 通过 `model.with_structured_output` 输出 overview、source_ids、gaps。模型选择相关来源和初步认识、保留本次缺口；程序从批准包构造唯一初始 T1 的目标、档案部分、完成标准、身份及依赖，不接受模型返回旧的大范围 tasks 或改写目标。完整包内的自主关联读取继续可用，不让用户预先找齐文件。

单个问题的主档案部分沿用选定发现的 section，不要求另外五部分重新建档或补写全项目缺口。执行复用现有 LangGraph、SQLite checkpoint、独立 worker、包内 MCP/RAG、原文读取、属性核对和有限补查。既有总调用/时间/字符预算及已知格式失败最多一次补试不变；最多两个并行任务，不新增执行样本、测试、修改或发布权限。

本轮 completed 要求任务完成、发现全部自动核对、本次主档案部分已有支持记录且计划无剩余缺口，只表示定向问题按本轮记录完成。目标是否实际回答、语义拆分是否正确仍有模型判断限制，离线契约通过不能证明线上理解质量。完整项目调查与版本增量仍沿用六部分收束规则。

新结果进入自己的档案及既有同版本知识路径。原发现保持原状态，M061 后续行动仍保留；定向调查本身不自动关闭旧问题。M063 提供单独的 [新旧结果审阅与结案](COGNITION_RESOLUTION.md)：完整对照包另行批准、模型逐项提出建议，用户显式采纳后更新当前有效认知和行动清单，旧报告保留。

新增指令和输出 Schema 纳入批准身份，未执行的旧契约包须重新准备，已完成历史继续只读。已保存的新定向请求可显式恢复复用；新请求结果未知仍禁止重发。新记录继续按项目存于 `.zest/state`，旧来源可在历史原位，避免历史搬迁。Web/终端页面未增加写入入口。
