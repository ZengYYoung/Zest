# M073：按证据要求与结论强度组织报告发现

M072 的 [真实评分](COGNITION_EVALUATION_M072.md) 在简单对照上符合预期，但真实长句把具体测试内容和“验证清洗”的概括混在一起，核对时仍出现遗漏或缩弱。用户同意本模块从调查报告生成端减少这种混合，复用现有 findings 列表；本模块不重写历史结论或改变评分标准。

## 生成规则

一条 finding 围绕可独立核对的断言组织。对象、所需原文窗口或结论强度不同的陈述分条，各自引用支持本项的实际原文；同一对象、同一证据和强度下的连贯字段组可以保留，不按标点或每个词机械拆分。

| 内容 | 生成方式 |
| --- | --- |
| 原文直接支持的具体事实 | observed，引用对应实际原文 |
| 原文直接且充分支持的概括 | 独立 observed，并给出足以支持概括的引用 |
| 需要推断但有依据的概括 | 单独 inferred，明确推断与依据 |
| 缺少依据、尚需读取或无法确定的部分 | 留 unknowns，不塞入 observed，也不借 inferred 凑数 |

例如一个用例只看见含空格输入，另一个用例看见行号断言，可分别报告这两项事实，清洗结果的验证缺口留未知。不会为了将报告压成约六条，把不同证据要求或不同强度的内容塞进一个概括句；六条继续只是软建议，完整响应字符、token、unknowns 数量和总调用预算不扩大。

同样区分测试输入/调用、结果断言、实际执行结果。只有输入不能生成“测试已验证处理正确”；原句只描述静态断言存在时，也不额外要求运行记录。有依据的概括和推断仍可保留，并非取消项目认知中的归纳。

## 修改范围与接收行为

更新研究提示及其派生的保留报告提示，ResearchFinding 的 kind/statement 和 InvestigationReport.findings 说明同步；ProjectResearchResponse 与 ProjectReportResponse 继续通过 model.with_structured_output 绑定具名 Pydantic。没有增加字段、拆分阶段、额外 Agent 或调用预算。

程序接收器仍负责结构、正文引用、敏感内容与资料权限，逐条隔离坏候选，保持原下标和顺序。生成语义由模型负责，接收器不按关键词判断句子是否复合、不自动拆句或改写历史文字。新指令/Schema 进入新批准哈希，旧包不能执行新请求；原始保存响应仍可按现有历史规则查看。
