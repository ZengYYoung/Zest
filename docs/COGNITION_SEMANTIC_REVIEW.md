# M065：移除模型字符索引，保留逐属性语义判断

M064 的真实核对响应声称覆盖完整，却给出与原句长度不符的 start/end，导致整批业务校验失败，见 [原始结果](PHASE_REPORT_M064.md)。用户确认精确字符计算不属于模型职责，本模块同步调整核对、独立评分和补查结案，不重构调查图或增加组件。

## 职责和 Schema

程序保存固定版本、完整原句、finding_id/reference_id、原文证据和哈希，校验身份、结构、引用、预算、批准和状态。新模型输出不含字符位置，不要求逐字复述或计算原句长度。

- ClaimCheck：subject、attribute、condition、assertion、evidence_ids、verdict、reason。
- ResolutionCheck：subject、attribute、condition、assertion、outcome、finding_ids、evidence_ids、reason。
- FindingJudgment / ResolutionJudgment 继续通过原身份关联整条原结论，并保留 coverage_complete、冲突和理由。
- 独立评分的覆盖度参考 ID、必要属性、固定分母和门槛保持原样；评分 Skill 同步取消字符索引要求。

所有固定结构仍使用具名 Pydantic 与 model.with_structured_output；新 Schema 拒绝旧 start/end 多余字段。没有改为只靠提示词要求 JSON，也没有自动补写/删除实际模型响应字段。

模型负责忠实拆分原断言，区分对象、属性、原条件、数量和否定，判断原文是否支持、是否存在冲突。不能为原句补入正确条件再判支持。coverage_complete 仅表示模型认为全部语义属性已核对；不确定或发现遗漏必须 false。程序不能证明该判断正确，不能以标志为 true 宣称语义没有遗漏。

## 接收和结案规则

新协议仍要求每个待评身份恰好一次、至少一个属性、支持项有本条获准证据。仅 observed、全部属性支持、模型判断覆盖完整且无未解决冲突时整条自动接收。推测、部分支持、证据不足或冲突继续待调查；不单独发布正确子项，不根据主题相似借用证据。

结案仍逐项检查新旧关联、直接冲突及未完成工作，用户显式 adopt 后才生效。移除字符索引没有取消候选证据约束、未知问句限制、冲突两端约束、预算、去重采纳或依赖失效检查。

## 历史与许可

已结束的认知/评分记录原位只读，原始 start/end、失败响应及历史分数不改写。结案 show 原本会重新校验保存结果，现按其冻结 Schema 选择历史范围校验，仅用于历史读取；原结果与采纳哈希不重算成新语义结果。

新外发仍核对当前指令、Schema 和 Skill。M064 的旧调查包、9 条字符扩展及未执行的 37 次评分包不能授权新请求。M064 保持 failed，不恢复、不改状态、不追加请求或发布知识。

## 离线验证与一次真实验证

优先复用 M064 首批四条核对的完整输入和保存响应。只在另存副本中移除 start/end，经过新 Pydantic、核对与评分校验；保留其余属性、条件、判定、理由和证据，证据不足项仍被阻断。此操作是显式的协议迁移夹具，不是新模型调用、语义正确答案或新成绩。

离线测试同时保留三类历史反例、冲突双方阻断、缺身份/坏引用、coverage_complete=false、推测拒绝、结案门控、历史结果读取和旧契约不能外发检查。

用户要求修复后进行一次真实验证。计划固定 M064 首批四条的原始输入，只替换本模块已变更的核对指令/Schema，使用现有 DeepSeek 适配器、ProjectReviewResponse 与生产接收器。**一次物理请求，0 补试，不运行整轮调查或完整评分**，不修改原数据库或把结果发布为项目知识。

修复提交后准备完整 payload、原文、指令、Schema、实际 SDK 请求/URL、模型、超时和输出预算，再按具体冻结包申请批准；需要字符扩展时与这条精确请求一起预览。不沿用 M064 剩余预算或已消费许可。收到任何结果均保存，无效/未知不重发。

单次成功只能验证这一批输入的新协议可处理，不能证明整体语义准确、全项目覆盖或补查结案线上质量。本模块提交时尚未执行真实验证。

后续 M066 经具体冻结批准，已执行唯一一次真实请求：四条返回均通过新 Schema 和生产接收器。模型全部判支持，但仍存在证据使用和支持边界疑点；没有执行独立内容评分或发布知识，详见 [单次验证结果](COGNITION_ACCEPTANCE_M066.md)。该一次调用许可已经消费。
