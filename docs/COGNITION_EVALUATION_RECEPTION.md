# M097：评分输出的额外字段接收兼容

日期：2026-10-16。用户确认修复[M096独立评分中断](PROJECT_EVALUATION_M096.md)。该次第2批在三个覆盖项各增加空`reason_extra`，评分主体已给出，但被闭合对象的本地校验整体拒收。本模块仅修接收兼容，不改评分准则或替模型决定语义。

## 接收规则

模型仍通过`with_structured_output(CognitionEvaluationResponse, strict=True, include_raw=True)`生成评分。供应商Schema仍禁止额外字段，必需字段与类型保持原样；本地仅在评分父模型入口建立副本，投影到已定义字段：

- 顶层`coverage/judgments`。
- 每个覆盖项、每个发现评分项。
- 发现评分中的每个属性检查、每个冲突项。

上述对象多出的备注或模型自报`overall_passed/supported/resolved`等不参与判定的字段被忽略，不写入正式评分结果；SDK安全原始收据仍保留完整供应商响应。已有字段的值、列表成员、顺序及文本不改写；未知字段不能代替缺失字段，不做类型转换、补字段、删评分对象、修复JSON或重发请求。

例如`{"id":"D2/auth", ... , "reason_extra":""}`可按原必需字段接收。但错误判定值、缺少`reason/evidence_observation`、多余或重复待评身份、错误候选/原文/冲突身份仍拒收。有效冲突继续阻止整条支持，模型额外自报通过不能覆盖程序汇总。

`EvaluationStore`使用具名Pydantic解析后的协议副本进行原有业务校验，保证真实SDK与本地模型适配器走相同规则。共享的覆盖项、核对、冲突模型单独使用时仍为闭合对象；问答、调查、原文核对、结案、规划等用途没有随之放宽。原来已确认的规划接收兼容保持。
