# 普通问答混合检索

混合检索默认关闭。`ZEST_QDRANT_URL` 留空使用进程内 Qdrant；填写 `http://127.0.0.1:6333` 可使用本机 Docker Qdrant 的 REST 接口（无需配置 6334）。不同存储位置的索引互不通用，切换后须重新构建语义索引。启用后，构建索引会向 Embedding 服务发送所选 Git 版本中允许读取的源码和文档片段；提问会发送问题到 Embedding，并向 Rerank 发送问题和候选片段。请先确认有权发送项目内容。已有敏感路径和凭据模式过滤不是完整的隐私检测。

1. 安装依赖：`uv sync --extra ai --extra web --extra hybrid`。
2. 在项目运行目录的 `.env` 中填写 `.env.example` 的 `ZEST_EMBEDDING_URL`（完整的 DashScope text-embedding 接口 URL）、`ZEST_EMBEDDING_KEY`、`ZEST_RERANK_URL`（完整的 DashScope text-rerank 接口 URL）、`ZEST_RERANK_KEY`。模型名称按实际服务配置，URL 和密钥不提交到 Git。如果运行 Zest 的进程已设置 `DASHSCOPE_API_KEY` 和 `DASHSCOPE_BASE_URL`（以 `/compatible-mode/v1` 结尾），可以直接复用：Zest 自动推导同域的 DashScope 接口地址。单独设置的 `ZEST_*` 值优先。
3. 在网页“项目状态 → 语义索引增量更新”先更新本地词法索引，再预览待发送片段、数量和配置；确认后才更新语义索引。也可执行 `zest index build PROJECT_ID`、`zest index build-semantic PROJECT_ID --preview`，确认后执行 `zest index build-semantic PROJECT_ID --allow-retrieval --plan-sha256 预览返回的plan_sha256`。CLI 中不提供哈希时，`--allow-retrieval` 是对执行时实际内容的直接授权；提供哈希可避免预览后内容或配置改变。预览不调用模型；执行只为缓存中缺失的去重片段调用 Embedding，会产生远程调用和费用。

   新格式在 Qdrant 中按内容身份共享向量，项目本地以原子文件仅保留最新发布和上一份语义版本来源映射。向量以项目、Embedding 接口、模型、可选模型版本标识、分块策略和片段原文哈希限定，在同项目内复用；即使文件改名或行号变化，相同片段也可复用，新的来源仍绑定新提交。`reused_chunks` 是复用的片段数，`new_vectors` 是需要调用的去重文本数。预览及网页确认通过哈希绑定提交、设置、缓存与待发送原文；发生变化需要重新预览。

   模型接口、模型名或分块策略改变时不会混用缓存。如果提供商以不变的模型名称更新权重，无法自动识别；需修改 `ZEST_EMBEDDING_REVISION` 重新建立向量。首次启用该缓存时不会自动从旧 Qdrant 集合导入向量。若部分批次成功后失败，新提交不会发布，但成功的向量留在缓存中供明确重试；不会自动重试。

   向量缓存位于项目私有状态目录 `embedding-cache.sqlite3`，包含可用于推断项目内容的向量，应按敏感项目数据保护。同一项目及模型配置使用共享 Qdrant 内容池，已有相同片段不会重复写入向量；提交切换只发布新映射，最多保留两份新格式映射。不再被两份映射引用的向量和缓存可在网页预览并确认清理。旧格式集合仍可按原版本读取，不会自动迁移或删除；历史或失败集合需要另行处理。现有索引、缓存和发布状态不属于 Git 共享文档。
4. 在 `.env` 中设置 `ZEST_HYBRID_ENABLED=true` 并重启服务。自动回答的普通对话使用混合检索；本地预览仍使用词法检索。命令行可使用 `zest project ask PROJECT_ID '问题' --retrieval hybrid --allow-retrieval --allow-model`，请以 `zest project ask --help` 为准。`--preview` 不调用检索服务。

项目状态中的索引状态只检查本地词法索引和语义发布标记，不检查 Qdrant 服务是否在线；实际查询仍可能降级。普通对话显示选定 Git 版本及检索路径；工作区有未提交修改时明确提示没有纳入证据。

两路各最多召回 20 条，按 RRF 融合后提交精排；证据从同一个固定 Git 版本重新读取并校验。词法索引缺失或版本不匹配会报错；向量索引缺失、Embedding 故障时降级为词法，Rerank 故障时降级为 RRF。对话显示实际路径，详细原因保存在上下文 warnings 中。手动指定文件仍优先，混合检索的源码排在知识记录之前。项目调查、文档生成未接入此路径。

## 评测建议

固定项目和 commit，准备覆盖精确符号、自然语言、跨文件和无答案问题的标注集，记录每题关键文件及必要证据范围。分别执行词法、混合（暂不配置 Rerank）、混合加精排，记录候选关键文件召回、最终上下文覆盖、人工判断的回答正确性及引用、端到端耗时，以及服务账单或供应商 usage。保留各次配置与原始结果，比较多题汇总和逐题差异。当前没有自动评分或费用统计；不要把模拟测试当成真实效果评测。

## 分块与 tokenizer

新建词法索引使用 `structure-cl100k-v1`：Python 源码优先按函数、方法、类及装饰器边界，Markdown 按标题边界；其他文本或解析失败时按原始行切分。每块最多 500 个参考 tokens、6000 字符、40 行，超出限制时继续切分，长文本窗口按最多三行重叠。单个超长行按 Unicode 字符范围切分并保存零基、右开列偏移；最终展示和精排前从同一 Git 文件重新核对。

参考 tokenizer 为离线内置的 OpenAI `tiktoken` `cl100k_base`，词表来源为 `https://openaipublic.blob.core.windows.net/encodings/cl100k_base.tiktoken`，SHA-256 为 `223921b76ee99bde995b7ff738513eef100fb51d18c93597a113bcffe865b2a7`。它不是百炼 `text-embedding-v4` 的 tokenizer；500 只是本地可复现的参考上限，并不等同服务端实际 token 数、硬限制或计费。符号定位产生的较大原文窗口也不受此分块上限约束。具体参数和效果尚未经过真实项目质量、时延、费用评测。

已有词法索引仍可读取，但不会自动变成新分块。对目标提交重新运行 `index build` 后，语义索引身份包含分块策略，旧向量不会作为新分块使用；需再经预览和确认执行语义索引更新；分块策略改变后旧向量不会直接复用。切换与升级期间语义检索会提示降级；旧格式 Qdrant 集合不会自动清理。

词法索引构建使用最近一份完整、通过校验的兼容索引作为基准，通过 Git diff 找出变化路径。目录树仍会遍历以执行路径过滤和预算检查；未变化且 blob 相同的已索引文件直接复用分块，不再读取其 blob。变化文件重新读取并切分；重命名按删除和新增处理，但可按 blob 和文件类别复用分块。旧格式、基准不可用、策略变化或 diff 失败时退回原有逐文件核对方式。语义索引预览仍回读全部目标版本片段并检查内容哈希，只对未命中缓存的去重文本生成向量。新语义格式在确认清理后删除不再引用的池向量和缓存，未提交工作区不参与检索。

## 历史与清理

新格式默认只保留最近两次成功发布的版本映射（当前及上一份），中间提交无需逐个索引；语义索引过期时普通问答降级，并按当前 Git 版本重新读取证据。该策略不自动索引新提交，须先建立当前词法索引、预览后手动确认语义更新。两版本以外的新格式历史可以按需重建或查询 Git；旧格式索引依然可读取且不会被静默删除。

项目状态提供“预览旧索引清理”：计划会核对当前项目与版本、两份保留映射、当前 Qdrant 池和缓存，列出不再引用的向量、缓存哈希及旧词法索引。确认时重新检查计划哈希；删除不操作 Git、源码、文档、任务或旧格式 Qdrant 集合。清理后的历史向量将来可能需要付费重建。当前范围仅清理当前模型与当前 Qdrant 位置的内容池与缓存；历史模型、其他 Qdrant 存储及旧格式集合不会自动清理。如果检测到旧格式语义标记，无法可靠确认其词法版本依赖，因此本轮保留所有旧词法索引。失败可能已清理部分派生数据，需要重新预览。

本地 MCP 提供只读 `git_history`（有界 commit 摘要，支持文件路径）、`git_changes`（两个完整 commit 的路径变化）与 `git_diff`（有界文本差异），可配合 `read_file` 读取历史原文。CLI 也可通过 `zest project history` 与 `zest project changes` 查询摘要和路径。提交说明是未经信任的摘要，不代表 diff 或完整事实；浅克隆会报告限制。普通对话使用有限的规则识别明确的历史问题，准备有界 Git 提交摘要；如果问题给出完整 commit 与文件路径，还准备该提交相对于第一父提交的有界差异。仅给出完整 commit 时提供变更路径，不将提交说明当作代码事实。模型依据这些资料回答；当前不是由模型自主、多轮选择和调用历史工具，未匹配的提问需要用户明确指定完整 commit 和路径。
