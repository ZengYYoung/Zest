# 普通问答混合检索

混合检索默认关闭。`ZEST_QDRANT_URL` 留空使用进程内 Qdrant；填写 `http://127.0.0.1:6333` 可使用本机 Docker Qdrant 的 REST 接口（无需配置 6334）。不同存储位置的索引互不通用，切换后须重新构建语义索引。启用后，构建索引会向 Embedding 服务发送所选 Git 版本中允许读取的源码和文档片段；提问会发送问题到 Embedding，并向 Rerank 发送问题和候选片段。请先确认有权发送项目内容。已有敏感路径和凭据模式过滤不是完整的隐私检测。

1. 安装依赖：`uv sync --extra ai --extra web --extra hybrid`。
2. 在项目运行目录的 `.env` 中填写 `.env.example` 的 `ZEST_EMBEDDING_URL`（完整的 DashScope text-embedding 接口 URL）、`ZEST_EMBEDDING_KEY`、`ZEST_RERANK_URL`（完整的 DashScope text-rerank 接口 URL）、`ZEST_RERANK_KEY`。模型名称按实际服务配置，URL 和密钥不提交到 Git。如果运行 Zest 的进程已设置 `DASHSCOPE_API_KEY` 和 `DASHSCOPE_BASE_URL`（以 `/compatible-mode/v1` 结尾），可以直接复用：Zest 自动推导同域的 DashScope 接口地址。单独设置的 `ZEST_*` 值优先。
3. 对登记项目先运行 `zest index build PROJECT_ID`，再运行 `zest index build-semantic PROJECT_ID --allow-retrieval`。第二步会产生远程调用和费用。每个管理版本需要独立构建；模型或 Embedding URL 改变后也需要重建。构建失败不会发布部分索引。构建标记存放在项目本地状态目录；向量保存在所选的进程内存储或 Docker Qdrant 中。重复构建可能留下未使用的集合，目前不自动清理。
4. 在 `.env` 中设置 `ZEST_HYBRID_ENABLED=true` 并重启服务。自动回答的普通对话使用混合检索；本地预览仍使用词法检索。命令行可使用 `zest project ask PROJECT_ID '问题' --retrieval hybrid --allow-retrieval --allow-model`，请以 `zest project ask --help` 为准。`--preview` 不调用检索服务。

两路各最多召回 20 条，按 RRF 融合后提交精排；证据从同一个固定 Git 版本重新读取并校验。词法索引缺失或版本不匹配会报错；向量索引缺失、Embedding 故障时降级为词法，Rerank 故障时降级为 RRF。对话显示实际路径，详细原因保存在上下文 warnings 中。手动指定文件仍优先，混合检索的源码排在知识记录之前。项目调查、文档生成未接入此路径。

## 评测建议

固定项目和 commit，准备覆盖精确符号、自然语言、跨文件和无答案问题的标注集，记录每题关键文件及必要证据范围。分别执行词法、混合（暂不配置 Rerank）、混合加精排，记录候选关键文件召回、最终上下文覆盖、人工判断的回答正确性及引用、端到端耗时，以及服务账单或供应商 usage。保留各次配置与原始结果，比较多题汇总和逐题差异。当前没有自动评分或费用统计；不要把模拟测试当成真实效果评测。
