## 行为与范围

普通 `project_plan` 继续绑定具名 `ProjectPlanResponse`，使用 `model.with_structured_output(..., method="function_calling", strict=True, include_raw=True)`。向供应商发送的 Schema 仍闭合、字段仍必需，提示和字段描述不变。

本地接收时只复制根对象以及 overview、tasks、gaps 中已声明的字段，再由原 Pydantic 严格校验。额外属性留在原始安全收据中，不进入执行计划，不作为新工具、来源、权限或预算。共享的子类型本身保持严格，定向补查、调查动作、报告、核对、评分、结案、问答和修改建议均不放宽。

缺必需字段、已知字段类型错误仍拒绝；不补 sections、不猜测字段别名、不按额外属性生成任务。之后仍调用原 validate_plan，检查来源、任务身份/数量/依赖、六部分覆盖及字段内容。原有响应字符/token保护、敏感输出检查、原始收据上限和已知格式有限补试保持。

普通规划的 output_contract 新增 local_reception=discard_unused_plan_fields_v1，明确将接收规则绑定到批准包；旧包在调用前拒绝外发。历史原始记录仍按原冻结身份保留，不自动迁移、接收或恢复失败规划。
