- 日期：2026-10-14
- 用户逐项确认：交互式终端工作台；主区对话 + 阶段时间线；第一个小模块只做问答闭环。
- 当前版本：问答/历史恢复及独立后台项目认知；选源为可选补充。

M053：项目认知 Ctrl+U 中新增“版本更新”，只读比较选定版本与既有档案证据并展示待刷新清单。生成过程显示真实阶段，支持返回工作台；不调用模型或改变旧知识。详见 [增量预览](COGNITION_REFRESH.md)。

## 1. 启动与使用

```bash
uv sync --extra ai --extra mcp --extra tui
uv run --extra ai --extra mcp --extra tui zest ui
# 固定状态目录，与现有子命令/Web 使用同一份项目及任务
uv run --extra ai --extra tui zest --state-dir /absolute/path/to/state ui
```

必须在真实终端中启动，不能将界面输出管道传给脚本。现有 JSON 子命令保持不变；没有登记项目时，工作台只显示接入说明，不创建项目或任务。先用 `project init` / `project import` 登记，再启动。

项目选择、问答历史、项目认知与原请求审阅位于顶部。主区对话/来源，侧边真实阶段和耗时。问答来源可选输入最多 5 个相对路径；留空使用默认材料及同版本知识。自主调查不要求用户先选源，入口与预算见 [项目认知工作流](COGNITION.md)。

输入问题后点击“准备问题”或 Enter。本地准备不调用模型，模型配置从现有本地 `.env` 读取；未正确配置时返回明确错误。准备完成后展开完整 target/payload、固定版本与批准哈希，可以滚动查看所有来源。

必须勾选已检查来源及目标，再点击“批准本次请求”；也可以拒绝或 Escape 返回。拒绝会保存状态，不调用模型。每个新问题都有新的任务和独立批准，不能继承上一个问题的授权。输入的问题不是 shell 命令。

回答显示引用原文、版本、行号和待补充信息。证据不足不等于已解决问题；来源 ID 合法也不证明模型结论的语义正确。终端只生成调查回答，不生成修复、执行测试或选择源码。

## 2. 进度与退出规则

四个真实阶段为：本地准备来源、审阅/批准请求、分析/核对结果、展示回答与引用。当前模型适配器不是流式接口，阶段与工作耗时提供反馈，不虚构完成百分比、token 流或更细的工具进度。

工作耗时统计准备及执行时间，不将人工阅读预览的等待计入。分析时界面仍可响应，项目切换和重复提交被锁定。完成、拒绝或失败后可以继续提问；任务保持原有 SQLite/LangGraph 持久化记录。

Ctrl+L 聚焦问题，Ctrl+Q / Ctrl+C 请求退出。后台执行中退出不等于取消，所以普通退出会提示等待本次有限超时；等待批准时退出保留任务，不默认拒绝或批准。强制结束进程仍可能留下待核对状态，不能自动重新计费调用。

### 2.1 重启后打开历史

点击“问答历史”或 Ctrl+H，选择当前项目的旧问答任务；列表显示状态、短 ID 和创建时间。列表仅从全局最近 100 项中筛选，并非完整历史；更早任务可输入完整 UUID。只显示 question 类型，修复建议任务仍使用原子命令。

打开时重新读取保存状态并核对项目/用途，展示原问题、创建时间和来源版本。其他项目或修复任务不展示正文。关闭历史选择窗口不改变任务状态；打开不会批准、调用模型或创建新任务。

- 已完成：展示原回答、未知项及原版本引用，不重新生成回答。
- 等待批准：先查看记录；点击“审阅原请求”才进入完整预览，仍需勾选后明确批准。重新读取最新状态，防止把其他入口已处理的任务当作仍待批准。
- 已拒绝/失败：查看已保存状态，不自动再执行。
- pending_execution / interrupted：明确执行结果未知，只读核对，不提供重试批准；不能保证原请求没有发出或没有计费。

恢复批准沿用原 task_id、来源 commit、target/payload 和哈希，不重新检索或换成最新仓库版本。原模型目标或知识有效性变化仍由既有服务阻止调用。需针对新版本调查时创建新任务并独立审阅。

切换项目会清空旧对话、输入和原请求审阅入口。历史回答不会自动成为新问题的上下文或长期知识；本次操作耗时不代表原任务的总耗时。

已有命令同样可以核对并继续等待批准的任务：

```bash
zest --state-dir /absolute/path/to/state task show <task-id>
zest --state-dir /absolute/path/to/state task approve <task-id> --payload-sha256 <show中的哈希>
zest --state-dir /absolute/path/to/state task reject <task-id>
```

不要对 pending_execution 盲目重试批准；当前服务会拒绝不处于等待批准的记录。

## 3. 实现与边界

使用 Textual 8.2.8 可选依赖，精确版本见 uv.lock。终端直接复用本地 ProjectRegistry、TaskRunner 和既有批准/结果校验，不要求额外 API 服务，也不在界面重新实现 LangGraph 流程。

阻塞操作在线程中执行，界面按主循环更新；取消界面协程不能承诺取消底层模型请求。[Textual Workers](https://textual.textualize.io/guide/workers/)

问题、来源和回答按普通文本显示，控制字符显式转义，不解释 Rich 链接/样式或 ANSI 命令。已识别凭据的问题不创建任务、不保存至会话记录或发送；模型密钥不进入预览。消息缓冲与可见日志有数量限制，完整任务记录仍由现有服务保存。
