## 本次停止原因

第2次响应的三个coverage项均未填写`finding_ids`，却分别判partial、partial、full。当前full/partial必须说明由哪些候选明确表达该属性，空数组不满足最低要求，因此整个批次保存为invalid，错误`evaluation_response_invalid`。

逐项限定payload的离线诊断确认三个空候选关联均被原业务校验拒绝。本批实际提供61条候选（20条已交付结论与41条未知陈述），包括模型自己提到的D_T3_F1；回复却称没有候选被指派为明确目标，混淆了requirements覆盖目标与candidates表达依据。D3/unknowns还返回full，而理由末尾写“结论侧仍为partial而非full”。这些是保存回复中的理解/判断问题；没有自动补身份、改判定或追加调用。
