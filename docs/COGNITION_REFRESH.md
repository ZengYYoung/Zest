# 增量认知：版本预览与待批准调查包

M053，2026-10-15。用户已确认先做选定版本变化检测、文件对比及既有证据关联。本模块生成后续调查的线索，不进行模型刷新、知识迁移或调查批准。

M054 在此基础上补上目标版本调查包准备，并复用既有规划/后台调查/原文核对流程；准备本身不会批准或启动模型。当前是手动触发、分别批准的增量调查，尚未证明真实模型的增量理解质量。

## 使用

```bash
zest cognition refresh-preview <project-id> --format text --progress
zest cognition refresh-preview <project-id> --format json
# 可选指定历史调查作为基线；新人无需先选择基线或文件
zest cognition refresh-preview <project-id> --base-run-id <run-id> --format text
```

终端工作台 Ctrl+U → **版本更新**，展示同一清单，可以返回认知工作台。真实阶段包含固定选定版本、读取基线、提交文件元数据对比及关联证据；CLI 进度写 stderr，JSON 结果单独写 stdout。

该入口读取已经登记的项目，无须模型配置。它不创建认知数据库、不迁移项目登记表、不更新旧记录；没有历史基线时明确提示先建立首轮认知。当前只有 CLI 和终端入口，Web 保持现有只读展示范围。

## 固定版本和基线

- 目标沿用源码选择规则：优先 `refs/zest/active/<project-id>`，否则使用开始检查时的 HEAD。未提交文件不参与对比；工作区脏状态单独提示。选定版本在对比期间变化时拒绝返回清单，需要重新检查。
- 默认优先选择目标 commit 已有的 completed/partial 调查；否则选择最近创建的已结束调查。显式基线必须属于本项目且已结束；活动、失败或拒绝的工作流不作为基线。
- 找到基线 commit 后汇总这个版本所有已结束调查的未失效发现，保持原 run/finding 身份。查询不受历史浏览器最近 100 条限制。包含 partial 调查时提示认知覆盖仍不完整。
- 两个 commit 都必须是本地可用的完整 ID。比较不要求祖先关系，支持分支切换和回退。没有提交、没有基线或基线 commit 已不可用分别说明，不伪造“无变化”。

## 清单内容

使用 Git 对象元数据比较新增、修改、删除、类型和权限变化，记录前后对象 ID/模式。重命名按删除旧路径与新增路径呈现，不使用相似度猜测。不会读取目标版本的文件正文，不跟随符号链接，不运行 external diff/textconv 或项目命令。

| 分类 | 含义 | 后续处理 |
| --- | --- | --- |
| directly_affected | 既有直接证据文件发生变化 | 纳入待刷新线索 |
| evidence_unchanged | 证据文件对象未变化 | 保留该观察；跨版本结论仍待核对 |
| unresolved | 缺失原文/窗口、证据身份不匹配，或基线不可读取 | 明确为无法核对，后续调查 |

每条发现保留原状态、类别、原始观察版本和证据窗口身份；证据无定位时不猜测。变更文件没有关联任何可核对的既有直接证据时，另列 uncovered_changes，避免仅关注旧认知而漏掉新增模块。

达到既有 large_scope_files（当前 200）数量时提示先商量按模块调查；清单本身不截断，也不增加调用预算或资料权限。已有凭据模式命中时以安全错误停止，不打印部分清单。

## 边界与后续

这是文件级影响线索，没有完整语义依赖图。某个文件内容未变，其结论仍可能被其他模块改变；因此版本变化时所有列出的旧发现都保留待目标版本核对提示，不能由清单直接获得跨版本知识资格。原 for_context 和修改来源验证规则保持不变。

当前清单处理认知工作流档案中的证据，人工长期笔记仍按原作用域处理。原有报告中的未知和任务待办继续保存在原档案，本模块不声称已经生成完整的后续调查计划。

只读预览不是执行授权。M054 可另外准备新 commit 的固定资料包，见下节；模型外发、包外资料、修改、测试和发布仍分别遵守既有授权规则。

验证包含 Git 变化/模式/符号链接、选择版本、脏工作区、跨 run 基线、缺失证据、原库字节不变、旧登记表无迁移、CLI 阶段/JSON 分离与 80×24 终端返回。它不证明模型理解质量或自动增量刷新已经实现。

## M054：准备并单独批准增量调查

```bash
zest cognition refresh-create <project-id> --format text --progress
# 可指定历史基线，默认沿用 preview 选择规则
zest cognition refresh-create <project-id> --base-run-id <baseline-run-id>
zest cognition preview <new-run-id>
# 审阅完整新资料包与哈希后，用户再决定是否批准；此命令会启动 worker
zest cognition approve <new-run-id> --approval-sha256 <new-approval-sha256>
zest cognition watch <new-run-id>
```

准备流程会读目标 commit 正文并保存新摸底及认知记录，需要现有模型目标配置，但不会调用模型或启动 worker。只接受本地可用且与目标不同的 completed/partial 基线；没有基线时先做首轮认知，同版本不冒充增量。准备期间选定版本变化则停止，已收集的固定摸底仍保留，不创建待批准认知工作流。

新包包含目标 commit 摸底所收录的完整安全文本，而非仅允许阅读修改文件；Agent 可以在这个新批准包内自主查找关联模块。摸底仍受已有安全规则和采集预算约束，不能据此声称收录了整个项目。变化目录完整保留，每项注明包内来源 ID、删除或包外；二进制、排除项等未纳入内容不会自动获得读取权限。目录容量有限时优先展示包内变化来源，实际批准范围仍为完整包。大范围变化、目录不完整和变更材料未入包会提示先确认范围，不扩展原预算。

`envelope.refresh_context` 固定基线身份、各 run 的批准包哈希、旧发现状态/内容哈希、变化元数据、未覆盖变化及调查重点。旧发现放在 `historical_leads`，只保存旧陈述和证据定位，不夹带旧正文或可引用的 R 编号；即使原为 auto_reviewed 或直接证据未变，也不是新版本共享知识。历史未知问题仍保留在旧档案，本模块未自动合并旧任务待办或人工笔记。

主 Agent 批准后才依据这些线索规划任务；任务 Agent 收到同一背景，仍须读取目标版本非空原文，再经既有独立核对进入新版本知识。删除元数据不证明功能消失或迁移位置，证据不足保留缺口。原同 commit 共享知识规则保留，旧版认知不迁移、不失效改写。

M055 起，新包和后续检查点存于项目 `.zest/state/`；基线也可来自旧版历史目录，按项目/commit 聚合，不复制历史批准或重发旧请求。每个数据库使用独立只读快照；身份冲突停止，见 [项目资源](PROJECT_RESOURCES.md)。

每次模型请求（含格式补试）及最后收束前会重新检查基线 run、旧发现哈希和状态；撤回、改写、增减基线发现或同版本调查集合变化时停止，要求重新准备。已经返回的响应和旧档案保留。准备后的 Git 分支继续移动不改变已冻结的版本/资料；后续调查仍只能依据批准包，不能偷偷切到最新 HEAD。

新工作流有独立 ID、完整包批准哈希和原有调用/时间/字符预算；旧调查的批准不能沿用。规划/调查指令新增了增量条件说明，未执行的旧包若契约已变须重新准备，完成历史不受影响。所有固定格式模型返回继续使用既有 Pydantic 与 `with_structured_output`，没有另开文本 JSON 解析捷径。上下文过大仍按已有暂停/单次扩展或预算收束规则处理，不截断历史线索后静默发送。

CLI 只增加函数入口和可读阶段；终端页面简化按用户意见后续参考 Claude 风格再做，Web 保持现有设计语言。本轮用离线模型夹具验证批准门、任务上下文、新版本证据、旧线索撤回及伪造旧引用隔离，没有真实模型调用、LangSmith 上传或增量质量结论。
