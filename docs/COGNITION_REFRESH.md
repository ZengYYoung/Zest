# 增量认知第一步：只读版本变化与证据清单

M053，2026-10-15。用户已确认先做选定版本变化检测、文件对比及既有证据关联。本模块生成后续调查的线索，不进行模型刷新、知识迁移或调查批准。

## 使用

```bash
zest cognition refresh-preview <project-id> --format text --progress
zest cognition refresh-preview <project-id> --format json
# 可选指定历史调查作为基线；新人无需先选择基线或文件
zest cognition refresh-preview <project-id> --base-run-id <run-id> --format text
```

终端工作台 Ctrl+U → **版本更新**，展示同一清单，可以返回认知工作台。真实阶段包含固定选定版本、读取基线、提交文件元数据对比及关联证据；CLI 进度写 stderr，JSON 结果单独写 stdout。

该入口读取已经登记的项目，无须模型配置。它不创建认知数据库、不迁移项目登记表、不更新旧记录；没有历史基线时明确提示先建立首轮认知。当前只有 CLI 和终端入口，Web 保持现有只读展示范围。

## 固定版本和基线

- 目标沿用源码选择规则：优先 `refs/zest/active/<project-id>`，否则使用开始检查时的 HEAD。未提交文件不参与对比；工作区脏状态单独提示。选定版本在对比期间变化时拒绝返回清单，需要重新检查。
- 默认优先选择目标 commit 已有的 completed/partial 调查；否则选择最近创建的已结束调查。显式基线必须属于本项目且已结束；活动、失败或拒绝的工作流不作为基线。
- 找到基线 commit 后汇总这个版本所有已结束调查的未失效发现，保持原 run/finding 身份。查询不受历史浏览器最近 100 条限制。包含 partial 调查时提示认知覆盖仍不完整。
- 两个 commit 都必须是本地可用的完整 ID。比较不要求祖先关系，支持分支切换和回退。没有提交、没有基线或基线 commit 已不可用分别说明，不伪造“无变化”。

## 清单内容

使用 Git 对象元数据比较新增、修改、删除、类型和权限变化，记录前后对象 ID/模式。重命名按删除旧路径与新增路径呈现，不使用相似度猜测。不会读取目标版本的文件正文，不跟随符号链接，不运行 external diff/textconv 或项目命令。

| 分类 | 含义 | 后续处理 |
| --- | --- | --- |
| directly_affected | 既有直接证据文件发生变化 | 纳入待刷新线索 |
| evidence_unchanged | 证据文件对象未变化 | 保留该观察；跨版本结论仍待核对 |
| unresolved | 缺失原文/窗口、证据身份不匹配，或基线不可读取 | 明确为无法核对，后续调查 |

每条发现保留原状态、类别、原始观察版本和证据窗口身份；证据无定位时不猜测。变更文件没有关联任何可核对的既有直接证据时，另列 uncovered_changes，避免仅关注旧认知而漏掉新增模块。

达到既有 large_scope_files（当前 200）数量时提示先商量按模块调查；清单本身不截断，也不增加调用预算或资料权限。已有凭据模式命中时以安全错误停止，不打印部分清单。

## 边界与后续

这是文件级影响线索，没有完整语义依赖图。某个文件内容未变，其结论仍可能被其他模块改变；因此版本变化时所有列出的旧发现都保留待目标版本核对提示，不能由清单直接获得跨版本知识资格。原 for_context 和修改来源验证规则保持不变。

当前清单处理认知工作流档案中的证据，人工长期笔记仍按原作用域处理。原有报告中的未知和任务待办继续保存在原档案，本模块不声称已经生成完整的后续调查计划。

后续再讨论如何把清单转换为新 commit 的固定资料包、调查任务和原文核对；模型外发、包外资料、修改、测试和发布仍分别遵守既有授权规则。此次只读预览不是任何一种执行授权。

验证包含 Git 变化/模式/符号链接、选择版本、脏工作区、跨 run 基线、缺失证据、原库字节不变、旧登记表无迁移、CLI 阶段/JSON 分离与 80×24 终端返回。它不证明模型理解质量或自动增量刷新已经实现。
