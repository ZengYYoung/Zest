# M069：评分目标与冲突线索的职责边界

M068 的 [真实评分](COGNITION_EVALUATION_M068.md) 在第二条停止：本批只要求 T1:F10，模型却为六条冲突线索也生成 judgments，并加入额外 note 字段。用户要求修复后复测；本模块修正 Skill 与结构化字段说明，保留原来的严格接收规则，不改评分标准或调查流程。

## 谁是评分对象

程序负责将整个评分范围安排为多批请求，模型只评价当前请求明确列出的目标：

| 输入 | 模型职责 | 对应输出 |
| --- | --- | --- |
| requirements | 判断本批必要属性覆盖 | 每个 id 恰好一个 coverage |
| candidates | 判断候选是否明确表达要求 | 为 coverage 提供候选身份，不增加 judgment |
| findings | 逐属性评价本批原结论 | 每个 finding_id 恰好一个 judgment |
| other_findings / report_unknowns | 检查目标与其他陈述的直接冲突 | 在目标 conflicts 中保留对方身份，不单独评分线索 |

线索标为 observed，或本批原文碰巧涉及它，都不改变其角色；重复、未读或证据不足本身也不是冲突。无目标的列表返回空数组。解释使用已有 reason，不新增 note 等字段。

内置 [评分 Skill](../zest/skills/cognition-evaluation/SKILL.md) 将原“审查包内全部 observed”改为“程序安排范围内全部 observed 进入各批 findings，模型只处理本批”。因此整轮评分仍审查全部 observed，包括参考之外的额外发现；本次澄清不缩减评分范围或固定分母。

CognitionEvaluationResponse 的 coverage/judgments 字段说明同步明确身份集合和各输入角色，仍通过 model.with_structured_output 与具名 Pydantic 绑定。未增加字段或动态组件，没有删除线索、裁剪响应、忽略 note 或从无效批次抽取可用部分。准则、证据权限、整条支持门槛、冲突、批准和零补试策略均不变。
