# Zest 的长期项目认知

- 日期：2026-10-14
- 状态：首轮固定版本认知建设已实现；持续增量更新与运行环境调查仍待后续设计。
- 使用与技术边界：[项目认知工作流](COGNITION.md)。

## 产品目标与协作

Zest 是长期参与单一项目的管理员 Agent，目标覆盖理解、开发、诊断、修复与更新。项目理解由 Agent 主动建立；新人不必先找齐源码和文档。用户介绍、补充资料和选源均为可选帮助。

开发模式从需求、实施和验证积累记录；导入模式调查代码、文档和配置建立认知。两种模式共用本工作流。登记不会直接外发仓库，首次调查需审阅完整资料包并批准。

已确认：本地摸底 → 主 Agent 制定初步认知与计划 → 按任务创建后台子 Agent → 原文核对 → 项目认知档案与共享知识。主会话持续可用；每个子任务结束后仍留存过程、依据和缺口。有原文支持的观察自动核对，需要人决定的设计/背景保持待确认；模型一致不是事实证明。

用户于 2026-10-14 选择一次批准有边界的调查：固定 commit、完整可审阅资料包、固定模型目标、工作指令和调用预算。子 Agent 可包内自主检索，每次请求留存；包外资料新建工作流再批准。此规则不能继承某次旧问答外发批准。

## 精简六部分档案

| 部分 | 内容 |
| --- | --- |
| 项目目标与业务边界 | 用户、功能、业务规则、解决的问题 |
| 模块与架构关系 | 模块职责、入口、协作关系 |
| 核心业务流程 | 关键操作经过的接口、函数和处理步骤 |
| 数据与外部依赖 | 数据声明、存储、外部服务和流转线索 |
| 开发与验证方式 | 配置、启动、测试方法及其证据性质 |
| 约束与认知缺口 | 设计约束、矛盾、未知背景和后续问题 |

每条发现保留任务、原文、物理行号、commit、blob 和内容哈希。区分 observed / inferred，以及待核对、自动核对通过、仍需调查、已失效。自动核对不等于人工确认，也不能保证语义正确。

例如配置声明 MySQL 可以由文件支持；生产实际使用 MySQL 需要运行证据；为何选择 MySQL 需要历史决策或人的说明。缺少证据时保留未知。“理解整个项目”是持续目标，一轮文档或模型自述不能证明完整理解。

## 当前实现分工

| 部件 | 当前实现 |
| --- | --- |
| 本地摸底 | 固定 Git 版本、允许文本、文档/声明、Python 地图、跳过与缺口 |
| 方法与契约 | 规划、调查、核对三类内置 Skill 指令，程序校验输出、引用、权限和预算 |
| 模型与工作流 | LangChain 适配器；LangGraph 协调图和独立任务图，SQLite 同步 checkpoint |
| 自主工具与 RAG | 包内只读 MCP：文件清单、词法 TF-IDF 检索、分段原文读取、Python 符号 |
| 后台协作 | 独立 worker，最多两个并行任务、依赖报告传递、有限补查 |
| 任务记忆 | 各任务图状态、工具结果、模型请求/响应、事件、发现和缺口 |
| 共享认知 | 同版本自动核对成果检索，接入问答、修改建议和后续认知资料包 |
| 用户成果 | 六部分档案，CLI 导出 Markdown，终端和只读 Web 展示进度与原文 |

共享认知是导航，不能代替源码。人的确认继续由 KnowledgeStore 管理，自动成果不伪装成 confirmed；历史问答也不自动变成事实。

## 实现边界与后续

- 固定版本调查，HEAD 变化不偷换资料包。新版本新建工作流；旧记录保留但不用于新版本上下文。
- 首轮不执行项目、测试、迁移或服务。支持允许文本，符号目前只支持 Python；历史决策、日志和生产环境需后续授权与工具设计。
- 预算有限，允许 partial。completed 仅表示本轮达到收束条件，不能证明完整理解；首个真实样本验收未通过，尚未产出核对成果，见 [验收结果](COGNITION_ACCEPTANCE_RESULTS.md)。更广样本与语义质量评价仍待进行。
- 活跃调查与修改建议按起始文件及已返回证据判断关联，尚无完整语义依赖图。候选修改、验证和版本选择仍须分别批准。
- 关闭界面不取消独立 worker。已知响应显式恢复可复用，未知请求不自动重试；没有强制取消或无人值守常驻服务。
- M052 起，认知新批准包包含单个请求最多一次已知格式失败补试；原请求不变、两次独立留收据并共用总预算，旧记录不重放。详见 [补试边界](COGNITION_RETRIES.md)。
- 增量刷新、主题长期记忆整合、运行证据、Web 写入和大仓库分批资料包继续独立设计。

预算、状态、恢复与使用集中在 [COGNITION.md](COGNITION.md)，计划内容见 [INVESTIGATION_PLAN.md](INVESTIGATION_PLAN.md)，验证见 [DEVLOG.md](DEVLOG.md)。
