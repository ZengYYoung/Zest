# 项目管理上下文总览

M057，2026-10-15。把分散在项目资源中的已有记忆、认知、索引和调查待办汇总为一个只读入口，帮助用户或连接 Zest MCP 的 Agent 确认当前掌握了什么、哪些内容还需核对。它不生成新的理解，不是模型请求，也不授予执行权限。

```bash
zest project context <project-id> --format text --progress
zest project context <project-id> --format json
```

`--progress` 在 stderr 输出实际阶段与耗时，JSON 保持在 stdout。阶段为固定选定版本、读取记忆、汇总认知/待办、读取索引和完成。查询不需要模型配置。

项目只读 MCP 增加 `project_management_context`，参数为空，绑定服务器启动时指定的项目；返回同一份 JSON。现有包内调查 MCP 的工具范围没有变化，不能据此把包外管理记录加入旧调查请求。问答和修改建议也不自动携带整份总览；原有固定上下文、批准与执行前复核继续生效。

## 内容与状态

| 内容 | 规则 |
| --- | --- |
| 版本 | 管理源码引用优先，否则 HEAD；未提交内容排除。查询结束复查选定 commit，变化则拒绝返回混合版本结果 |
| 人工记忆 | confirmed 的项目级记忆及同 commit 版本记忆列为适用；草稿、失效或其他版本单独列出身份/状态，不输出正文作为当前记忆 |
| 六部分认知 | 同 commit、已结束 completed/partial 调查、auto_reviewed、observed 且保存的来源身份与批准包匹配时，列为自动核对事实；推测、失效、来源不完整及未结束调查发现放在待核实栏 |
| 历史调查 | 仅列 run 身份、commit、状态、时间和调用数，不把旧发现或旧缺口搬进当前事实 |
| 索引 | 只返回当前 commit 索引的原生路径、blob、内容哈希与行段窗口；不返回缓存正文，不自动建立或更新索引 |
| 缺口 | 当前版本规划问题、任务未知、包内补读/包外资料需求，以及报告中未接收的候选；保留来源 run/task，不自动去重或宣称问题已经解决 |
| 调查待办 | 列出未结束、待批准、待扩展、失败或结果未知的调查，并提示审阅/核对入口；历史版本待办明确标记，不启动 worker 或恢复请求 |
| 后续行动 | M061：当前版本 completed/partial 调查的 observed 发现中，pending_review/needs_investigation 提供核对/补查入口；推测、失效、其他版本和仍在运行的调查不进入此清单 |

这里的待办只包含认知调查，不声称汇总了全部问答、修改、验证和源码切换任务。六个部分中有记录的数量是导航统计，不是认知质量或理解完整度评分。

## 已结束调查的后续行动

M061 在 `cognition.followup_actions` 中单独列出已结束调查尚需处理的 observed 发现；原 `cognition.todos` 继续表示调查级待办。例如调查 partial 后调用预算耗尽，调查级待办可以为零，但尚未核对的发现仍有后续行动。推测、一般未知、资料需求和已失效记录保持原栏目，不自动转成行动或推定已经解决。

每项使用稳定的 `run_id/finding_id` 身份，保留 commit、任务/发现/调查状态、原结论、来源行段与哈希、保存的来源身份核对结果、核对明细、原调查停止原因，以及 conflicts/conflict_links 两侧的定位和原因。冲突逐条保留，不自动合并语义或判定消解。pending_review 提示需要核对，observed/needs_investigation 提示需要补查；保存来源缺失或不匹配时优先提示检查来源身份。

`inspect_command` 是带本次登记目录的现有 `zest --state-dir … cognition show <run-id> --format json` 参数数组；CLI 文本以安全引用显示，用户可在该记录里按 finding_id 查看保存的完整原文和核对结果。总览保留来源导航，原文仍在原调查记录，没有另建正文副本。查询不执行该命令，也不创建任务、批准、worker、重试或恢复记录；需要继续模型核对/补查时另行准备和批准，不能沿用已经结束调查的旧许可。

清单每次从当前保存状态派生，不落盘新的待办库或修改原记录。发现变为已核对或失效、或项目选定版本变化后，重新查询即可反映变化；这只表示不再符合本清单条件，不代表其他未知和缺口消失。JSON 采用兼容的新增字段，schema_version 保持 1，旧调查级待办含义不变。

## 完整性与只读边界

读取沿用项目内 `.zest/state` 和原历史存储路由，不迁移或复制记录。管理清单不沿用问答的前三条筛选、认知检索的候选数量或历史浏览 100 条限制；`records_truncated=false` 表示这些登记记录没有为展示截断，并不表示材料或调查本身覆盖了整个项目。JSON 保留完整清单与来源字段，文本用于阅读主线。

缺失的记忆/认知/索引库保持缺失，不创建空库；已有库以只读连接访问。当前 commit 没有索引统一表示 `no_current_version_index`，不冒用历史索引。损坏、重复 UUID、资源身份冲突、已识别凭据等明确报错，不显示一个看似完整的空结果。初始化状态、文件内容/修改时间、批准哈希、任务、Git 引用和索引均不因查询改变。

各数据库分别使用读取快照，未引入跨数据库全局事务。总览记录读取时的版本和状态；后续失效或新结果需重新查询，实际执行仍须走原有来源复核。认知证据只检查保存的来源身份与批准目录一致，没有在本次查询重新读取原文、复核语义或证明生产运行；自动核对不等于人工确认。

本模块不落盘新的 Markdown、覆盖 `.zest/AGENTS.md` 或扫描/执行任意 skill。首次初始化的导航模板增加查询入口，已有管理指引不被改写。新的认知调查仍需审阅独立固定资料包；总览中的内容不会自动加入旧批准或触发模型外发。

## 验证

临时 Git/SQLite 仓库覆盖无登记/无提交、当前与历史版本、管理引用优先和脏工作区、记忆状态、六部分分类、来源身份异常、未知请求待办、旧新布局、多项目隔离、超过历史/上下文筛选上限、损坏/重复/敏感记录、读前后资源字节与修改时间不变，以及 CLI 实际阶段。离线生产认知流程生成的六部分记录进入总览；真实 MCP 客户端验证只读工具读取。没有新增真实模型调用或项目执行，测试不代表理解质量验收。

M062 为保存来源身份匹配的后续行动增加 `prepare_command`，指向 [同版本定向调查包](COGNITION_FOLLOWUP.md) 的 followup-create。总览仅提供参数和说明，不执行命令；真正准备会保存新资料包，随后还需独立批准。

M063 将明确采纳且依赖仍有效的处理决定用于只读筛选：已解决旧发现进入 `cognition.resolved_findings`，包含原状态、旧句和 `resolution`（处理记录、结果、新 run/候选、时间与建议哈希），退出当前 facts/pending 和后续行动；一般未知仍保留，明确回答的关联未知仅追加标注。原调查库不修改。

依赖变化时追加 `inspect_resolution` 行动并提供完整决定预览入口，恢复待复核提示，旧错误继续排除在有效知识之外。原状态仍是 pending_review/needs_investigation 才保留 M062 准备命令；auto_reviewed 的旧关联结论不伪造为 M062 可选来源。管理总览不采纳决定、不启动模型。详见 [结案规则](COGNITION_RESOLUTION.md)。
