# Zest 本地项目摸底

- 模块：M030，固定版本材料采集与独立记录。
- 状态：已实现；主 Agent 规划、后台子任务与自动知识核对尚未接入。
- 无新增依赖，使用已有 Git 读取、声明解析器、Python AST 地图与本地 SQLite。

## 1. 使用

对已登记项目执行一次摸底，查看真实阶段和可读摘要：

```bash
uv run zest survey build <project-id> --format text
uv run zest survey list <project-id>
uv run zest survey show <survey-id> --format text
```

默认 stdout 为 JSON；`--format text` 提供可读摘要。真实终端默认在 stderr 显示阶段、已收集文件数及实际耗时；脚本默认不输出进度，可用 `--progress` 明确开启。开启时 stdout 仍为独立 JSON，完成保存后才显示记录 ID。

```bash
uv run zest survey build <project-id> --progress > survey.json
uv run zest survey build <project-id> --commit <完整本地commit> --format text
uv run zest survey show <survey-id> > saved-survey.json
```

所有命令沿用 `zest --state-dir /absolute/path/to/state ...` 选择登记入口。`project import` 会登记并准备项目内忽略的 `.zest/` 资源目录，不自动摸底或启动模型任务。

## 2. 输入与成果

默认固定开始时的管理源码版本，未选择管理源码时使用当时 HEAD。可显式指定本地完整 commit，不接受分支、缩写或远程版本。工作区变更不进入材料，工作区观察状态单独保留。

摸底记录包含：

| 内容 | 保存信息 |
| --- | --- |
| 项目与来源 | 项目 ID、记录 ID、创建时间、固定 commit、工作区观察状态 |
| 目录与文本清单 | 递归目录及 tree ID；通过检查的文件路径、blob ID、完整内容 SHA256、字节/物理行数 |
| 分类线索 | 文档、依赖声明、代码、入口及测试候选；命名/路径启发式不代表实际运行入口或可执行测试数量 |
| 文档与声明材料 | 有预算的原文片段、行段、片段哈希与截断/省略说明；Python/Node 声明解析结果 |
| 源码结构 | 同一 commit 的 Python 静态声明地图，包括声明、import、来源、覆盖与限制 |
| 六部分调查入口 | 档案六部分对应的材料 ID 与程序预设调查问题，全部保持 pending_investigation |
| 缺口与覆盖 | 已接受/尝试文件数、跳过原因、预算中断、未支持解析、缺失材料及尚无运行验证 |

六部分入口是后续规划的输入，不是模型制定的调查计划，也不是已建立的业务认知。未找到材料只表示本轮允许范围内未发现，不证明项目中一定不存在。

文档/声明可在嵌套目录中发现；JSON/TOML 解析使用已有解析器，但先经过共享安全文本读取。Java/JVM、Go、Rust 等依赖声明先记录原文与来源，明确 inventory_only；其他代码语言只列材料并标记结构解析缺口。

## 3. 边界与预算

仅从 Git tree/blob 读取，不导入模块、不安装依赖、不运行项目脚本、声明命令或测试，不调用模型、不构建 RAG 索引、不写入共享知识。复用已有 Git 环境、过滤器及 fsmonitor 隔离规则。

沿用允许文本扩展名、256 KiB 单文件上限、UTF-8/二进制检查及已知凭据模式排除；新增元数据路径长度/编码/凭据检查，排除受保护目录及链接/子模块，不跟随工作区路径。检测基于已知模式，不承诺发现所有秘密。

材料清单最多尝试 200 个通过路径检查的候选文件、接受 4 MiB 文本，最多查看 4096 个树条目；目录深度与路径长度有上限。30 秒为操作间检查的扫描预算，不是可强制中止 Git/解析的硬时限。聚合文本预算在读取文件后检查，可能读取一个触发上限的额外文件；被排除文本不进入保存材料。

文档/声明片段最多 80 物理行、6000 字符，全部片段最多 24000 字符；超限保留来源和省略原因，完整内容不会被截断后伪装成全文。Python 地图另用原有 100 文件/4 MiB、声明/节点/时间预算，独立统计，其结果仍固定在同一版本。

`collected` 表示本轮材料采集结束，仍须查看跳过与截断记录；预算中断或源码/声明解析警告可形成 `partial`。尚无提交时保存 `no_committed_source` 及缺口，不形成虚构版本。

## 4. 保存与历史

新接入项目在 `.zest/state/` 内生成 `surveys.sqlite3`，旧记录原位兼容，新数据库权限为 0600。记录按独立 UUID 追加，重复采集不会覆盖旧记录。每个历史来源的 `list` 为最近 100 项摘要，合并展示不等于完整分页；完整 ID 可读取更早记录。[项目资源说明](PROJECT_RESOURCES.md)

保存前限制序列化记录为 8 MiB，保存内容 SHA256 并在读取时核对内容及身份一致性。这用于发现损坏，不是签名或对恶意数据库篡改的认证。

`show` / `list` 用只读连接，不重新扫描仓库；仓库移动后仍可查看已保存结果。没有数据库时查询不创建新状态。出错返回稳定错误码；采集或保存失败不覆盖既有历史，也不自动重试。
