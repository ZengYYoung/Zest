# 逐项属性核对与冲突保留

M059。核对仍复用原有单轮 Agent、批准包和 SQLite 账本；本模块不增加模型调用阶段。

每条发现的 statement 保留原样。核对 Agent 用具名 ClaimCheck 逐项返回原句字符范围、对象、属性、原断言条件、断言、关联原文及 supported / contradicted / insufficient_evidence 判定。范围按 Unicode 字符计数，含起点不含终点，连续覆盖整个原句。模型不能修正条件后替原断言判支持。

程序要求每个 finding 身份恰好出现一次、原句全字符覆盖、支持项有其关联 P 原文、不借用其他发现的证据；仅 observed、全部命题支持、coverage_complete=true 且没有未解决冲突时整条 auto_reviewed。部分正确仍保存明细，整条保持 needs_investigation，不单独发布正确子项。字符覆盖不证明语义拆分完整；coverage_complete 仍是模型判断，离线测试不能证明模型已掌握拆分或语义。

任务 unknowns 以 Tn:Um 身份进入核对输入，与 other_findings 都只作为冲突线索，不成为正文证据。对同一对象、属性、条件的不兼容陈述保存 reference_id 和原因。跨批发现冲突时，同 run 的另一方即使已自动接收也降为待调查；先前 invalidated 不复活。关联冲突不会因为另一批简单返回支持而消失。本模块保守保留冲突，自动消解与跨 run 追溯分别设计；历史 M058 不重评或改写。

例如 fixture 的创建方式、关闭行为和生命周期应分别判断；空输入与非数字的错误分支不可混用；配置值存在与其行为解释应分开。它们是核对维度的示例，不是针对 pytest 的硬编码规则。框架默认语义缺少包内依据时保持证据不足，不能把内部常识冒充原文或擅自联网。

ProjectReviewResponse 继续通过 with_structured_output 生成，supported 改为程序派生的内部字段。新指令和 Schema 进入新批准哈希；旧批准不能执行新契约，已结束历史仍可读。原有一次格式补试、精确请求冻结、预算和未知请求不重发规则保持生效；语义或字符范围业务校验失败不触发格式补试。

离线验收包含三类历史反例的人工标注判定及正确对照、部分支持、遗漏范围、坏引用、冲突定位、跨批双方阻断和恢复边界。保存的真实输入用于确认缺陷与资料身份；没有将旧 supported=true 响应变造成新模型正确输出，历史成绩不变。
