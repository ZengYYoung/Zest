## 问题与最小修改

[M076](COGNITION_EVALUATION_M076.md) 中，评分模型读到字面量 `mixed case`，仍将“全小写且无空格”一并判为supported，理由也复述无空格。原句没有丢失，协议没有失败；问题在于具体值及描述属性没有被可靠比较。合并属性是可观察到的现象，不能据这一次响应断言它就是所有误判的原因。

本模块按已确认范围，在一次结构化评分响应内显式区分证据观察与原断言判断：

1. 对原句实际声称的可独立判真属性分别核对；具体值与它的大小写、空白、单位、边界或行为解释分别处理，不按标点机械拆句，不给所有对象套同一清单。
2. 每个评分check必须给出`evidence_observation`：简述该项获准P原文显示的实际值、行为或条件；缺少所需内容时说明可见范围及缺口，不能照抄待评断言作证据观察。
3. 再用verdict和reason说明实际观察与原assertion的关系。否定、量词、条件和原断言强度保持不变，仍区分supported / contradicted / insufficient_evidence。

例如，原句同时描述某个字面量及“无空白”时，值是否相同、是否含空白需要各自判断；值对上不能替描述背书。此原则写入通用Skill，没有把M076的字符串或对照答案写进模型指令。

## 具名协议与接收

`CognitionEvaluationResponse.judgments`改用具名`EvaluationFindingJudgment`，checks为`EvaluationClaimCheck`，仍经`model.with_structured_output`绑定。字段顺序为：subject、attribute、condition、assertion、evidence_ids、**evidence_observation**、verdict、reason。

evidence_observation为必填严格字符串，非空、不能只有空白、最多800字符；原样保存，不裁剪或替换。模型不返回字符位置。需要原文时只使用该finding允许的P身份，原文身份校验仍适用；缺少资料也必须明确写出缺口。它是模型对原文的描述，既不是新来源，也不是程序已证明的事实。

具名Pydantic与评分业务接收器都要求该字段；缺失、空值、错误类型、超长或额外字段不补写，借用其他发现/未知或伪造P身份仍不能成为有效支持。原文核对继续用原`ClaimCheck` / `FindingJudgment`，结案协议保持原样；其他八种模型输出的完整契约与修改前一致。共用校验函数只有评分入口显式启用观察字段要求，原文核对仍按自己的封闭字段集校验。

接收器继续基于模型给出的检查完整性、verdict及冲突派生整条支持；不增加自然语言关键词解析器，也不根据观察文字擅自改标签。新增字段使证据解释可独立查看，但字段顺序和格式有效不证明模型真正正确观察或完成了比较。离线反向对照还故意保留“观察说有空格、标签仍supported”的错误，验证程序不会偷偷修补结果。

覆盖参考项的CoverageJudgment没有扩展字段，原分母/门槛、整条门控、引用和冲突规则不变；本模块只调整逐发现语义评分。没有增加Agent、模型调用轮次、任务图、预算、工具或外发权限。
