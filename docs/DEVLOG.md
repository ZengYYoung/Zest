# Zest 开发日志

每个小模块独立提交。日志与实现放在同一次提交中，记录目的、变化、验证和限制。提交标题用作关联键，可通过 Git 历史查到对应 commit；不在日志中嵌入自身提交的哈希。

## 2026-10-13 — M001：本地 Git 项目登记

提交标题：`feat(projects): add local Git project registration`

### 目的

为导入模式建立可运行的基础：先确定正在管理哪个仓库、哪个版本，以及采集时工作区是否存在未提交修改。项目理解、代码检索和修复等功能以后基于此继续扩展。

### 本次实现

- 建立 Python 包与 CLI，当前运行只依赖 Python 3.11+ 和 Git。
- `project import` 检查本地 Git 仓库根路径，只读查询分支、HEAD、脏状态及暂存/未暂存/未跟踪项统计。
- 支持空仓库、分离 HEAD、Git worktree 和中文/空格路径；拒绝普通目录、文件、bare 仓库及仓库子目录。
- 使用本地 SQLite 保存项目登记，规范化路径用于去重；重复登记保留原项目 ID 和创建时间，更新采集结果。
- `project list/show` 读取持久化记录；错误使用非零退出码和 stderr JSON。
- 查询时移除继承的 Git 环境覆盖，禁用 fsmonitor 与可选 Git 写锁；新状态目录和数据库使用受限权限。
- 补充 README 运行说明、总体设计实现进度及 `.zest/` 忽略规则。
- 将此前撰写但未提交的总体设计文档一起纳入本次开发基线。

### 验证

执行：

```bash
python3 -m unittest discover -s tests -v
```

结果：**25 项通过**。本次验证环境为 macOS、Python 3.13.9、Git 2.54.0；尚未单独验证其他 Python 版本或操作系统。案例使用临时目录中的真实 Git 仓库，包含：

- 空仓库、正常提交、分离 HEAD、Git worktree。
- 同时存在暂存/未暂存/未跟踪修改，以及带换行符文件名的重命名。
- 重复登记、路径别名去重、跨进程读取和未知项目。
- 无效路径、不兼容数据库版本、数据库损坏及规范 JSON 错误。
- 继承 Git 环境无法重定向查询，fsmonitor 脚本不执行。
- 采集前后目标文件和 Git 索引字节保持一致。
- 采集过程中 HEAD 变化会被拒绝。

此结果验证的是项目登记模块，不代表已验证 Agent、RAG、修复、部署或生产回退。

### 当前限制

- 登记是元数据采集，不复制代码，也不是未提交文件的不可变快照。
- `list/show` 展示上次采集结果；需再次 `import` 才会刷新。
- 未跟踪目录可能按一项统计，不等于文件总数。
- SQLite 状态绑定指定状态目录；完整用户权限、历史快照和生产部署尚未实现。
- 第一模块不接入 LangChain/LangGraph/MCP 或模型 API；这些能力待相应功能确定后接入。

### 下一项建议

只读项目概览：在已登记仓库中识别少量可验证的项目入口、依赖声明和文档位置。具体内容先讨论，不在本次提交内扩展。

## 2026-10-13 — M002：只读项目概览

提交标题：`feat(projects): add committed project overview`

### 目的

在已登记项目上建立第一份有版本来源的结构概览，为后续项目问答提供可验证的资料位置。先输出确定性事实，不让模型凭目录名称猜测业务架构。

### 本次实现

- 增加 `project overview <project-id>`，查询时选择当前 commit，不读取工作区或暂存区内容。
- 按 Git tree/blob 读取数据，所有文件引用保留路径、commit 与 blob ID。
- 解析根目录 `pyproject.toml` 的标准项目元数据、依赖和 scripts，以及 `package.json` 的项目、依赖和 scripts 声明。
- 对 Java、Go、Rust 等已识别构建/依赖声明只列出位置，不声称已解析其依赖。
- 列出根目录 README、一级文档位置、根目录及常见入口候选；命令声明只返回数据，不执行。
- 明确提示脏工作区、登记 HEAD 过时、解析失败和数量/大小限制。
- 不跟随符号链接，不读取非白名单文件内容；Git 对象查询关闭按需拉取和 replace 对象，避免隐式网络访问或替换来源。
- 更新 README、总体设计和开发日志。

### 验证

```bash
python3 -m unittest discover -s tests -v
```

结果：**43 项通过（M001 25 项 + M002 18 项）**，验证环境为 macOS、Python 3.13.9、Git 2.54.0。

新增案例覆盖：

- Python/Node 元数据、依赖、命令声明和证据 ID。
- 暂存、未暂存和未跟踪内容被排除；新提交触发登记过时提示。
- 读取过程中 HEAD 改变，文件仍来自最初选择的 commit。
- 符号链接、已跟踪 `.env` 和生成目录不被采集内容。
- 无效格式、错误字段类型、非 UTF-8 和超大声明的降级提示。
- 一级文档范围、特殊文件名及文档数量截断。
- 目标工作区和索引不被修改，项目移走和未知项目返回规范错误。

### 当前限制

- 仅分析已提交内容，未提交代码不纳入概览。
- 概览即时生成，不保存历史，不自动更新登记记录。
- 常见文件名只是入口候选；命令声明、依赖声明未经过运行验证。
- 文档只列出位置，业务逻辑、调用关系、RAG 和模型问答仍未实现。
- 非白名单文件不读取，但白名单元数据本身仍可能含敏感信息；当前只本地输出，尚未设计向模型传输的脱敏。

### 下一项建议

读取指定 commit 下的单个允许文件，带可追溯行号和内容标识返回，为后续项目问答建立证据读取能力。
