# M071：区分检查完整性与证据支持

M070 的 [真实评分](COGNITION_EVALUATION_M070.md) 在一条属性上写 supported，理由却承认证据不完整，再用整条 coverage_complete=false 阻止接收。另一条把测试输入/意图解释为足以支持清洗结果概括。用户确认本模块统一这两个字段的职责，并明确证据能支持的结论强度。

## 两个独立问题

| 字段 | 回答的问题 | 不能代替的含义 |
| --- | --- | --- |
| coverage_complete | 原句全部独立属性、限定和概括是否已逐项检查 | 不表示证据充分或整条正确 |
| checks[].verdict | 本项原断言是否被其获准证据完整支持、有相反证据或证据不足 | 不能用检查完了来证明支持 |

所有属性都已检查，即使其中有 contradicted/insufficient_evidence，也可以 coverage_complete=true。遗漏或无法确认拆分完整才为 false。仅支持原属性的一部分、缺原文窗口/条件/语义依据时，使用 insufficient_evidence；有相反证据才 contradicted。reason 应与本项判定一致，不能在 supported 的理由中承认原断言尚有未支持部分。

整条接收规则不变：observed、检查完整、所有属性 supported、无未解决冲突，缺一不可。程序继续检查身份、结构、引用和状态，保留模型原判断；没有添加以关键词解读 reason 的语义校验器，也不自动改标签。

## 忠实保留原断言强度

| 可见证据 | 可以支持的陈述 | 还不足以支持的陈述 |
| --- | --- | --- |
| 测试输入及调用 | 测试使用这个输入、调用这个函数 | 已验证某个输出或实际通过 |
| 结果断言 | 测试要求这个结果 | 当前版本已经实际执行通过 |
| 对应版本/范围的获准运行记录 | 该次记录覆盖的实际结果 | 未运行的其他分支、版本或环境均通过 |

原句只描述输入或断言时，静态原文可以充分支持；不额外要求执行测试。原句声称验证结果或实际通过时，不能缩成较弱的输入事实后判支持。配置声明、行为保证和运行结果也按原句实际强度分别判断。

模型负责这些语义判断，并检查条件、量词、否定、括号与概括。例子帮助说明准则，不预设真实样本应当得出哪个答案，不将其当作完整项目评分参考。
